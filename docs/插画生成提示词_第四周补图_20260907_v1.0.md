# 第四周补图生成提示词与来源 v1.0

**为什么补**：第四周词卡墙（`taughtWords()` 34 词）里 pan、tip、tap 无图，但第四周 WORD_ILL 已有同名图，只把 `W[].art` 从 null 填成同名键即可；另五个 W 表词 dan、nat、nap、rag、pats 在造词工坊 `showWordPicture(word)` 按 `W[word].art` 取图时缺图，按用户要求用 codex 订阅生图补齐。认读词（i、a、see、the、is、to）按周课件设计规范不配图；it、on 抽象不配。

## 出图管线（与第三周文档 §0 的差别）

- 生图：codex CLI `image_gen`（`codex exec --skip-git-repo-check --sandbox workspace-write -C <可写目录> -m gpt-5.6-sol [-i 参考图 …] -- "$(cat 提示词)" < /dev/null`）；1024×1024 白底 PNG。踩坑：后台运行必须关闭 stdin，否则 codex 等输入挂住；`-i` 会吞掉后面的参数，提示词要放在 `--` 之后。
- 风格前缀：照抄 `插画生成提示词_第三周_20260902_v1.0.md` §1，一字不改；`pats` 加 §0.6 关系场景条款。
- 规格化：先只抠与画布边缘连通的近白像素（亮度 > 242 且饱和度 < 18），保住眼白与鞋带；再 `unify_card_outlines.unify`（192 px、3 px 深描边、8 px 留白）；内部残留的透明小点用四邻域不透明色填回（nat 4 像素、pats 42 像素）；断言无内部透明洞、四边留白 ≥ 8、长边 85% 到 95%。
- 落盘：第四周插画无文件源，`embed_assets.py` 按目录全量重建会清空其余插画，所以规格化后的 data URI 直接追加进 `frontend/src/media/week04/word_ill.js`（媒体声明是当前真相源，`test_media` 校验生成 == 源）；原图存 `resources/assets/week04/word-cards/`（见该目录 README 的警告）。工程健康化第 1 期导出到 `resources/adopted/` 后，这五张按新管线迁移。
