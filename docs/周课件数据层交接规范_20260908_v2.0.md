**你要做的**：写出第 N 周的**课程数据层**——一个 JS 文件，里面是音素教学数据、词库、七天课程、小书故事、四个游戏的题库、以及所有给孩子和家长看的文案。

一句话：**你写内容，引擎和媒体在这边。**

## 3. 数据层 schema

### `META`

```js
const META = {
  week: 5,
  storageKey: 'soundblocks-w5-v1',

  // 周型四维，互相正交，见 §4.3。不要用单一枚举描述一周。
  teachingMode: 'phoneme',      // 'phoneme' 教新字位 | 'skill' 教新技能 | 'none' 不教新东西
  consolidation: false,         // 是否复习巩固周（与 teachingMode 正交：W20 两者都是）
  bookMode: 'new',              // 'new' 有正文的小书（含复读合集）| 'none' 本周无小书
  externalReading: false,       // 是否另有外部可解码读物轨（与 bookMode 正交）
  assessmentMode: 'weekly',     // 'weekly' | 'monthly' | 'stage' | 'annual'

  newPatterns: ['ai', 'j'],     // 本周新字位 ID，空数组 = 不教新字位
  wallLetters: [...],           // 点亮墙字位 ID 数组，取值规则见下
  rackG4: ['r','ai','n', ...],  // G4 点单积木架，每个元素一块积木
  rackG5: [...],                // G5 造词积木架，同上
  flashCapacity: { flash_words: N },
  newWordPatterns: ['CCVC'],    // 本周新词形，供 DATA-GRADIENT-01 判定；没有就空数组
  noveltyPolicy: {...},         // 新旧词配比，见 §4.1。由课程配置给出，不由执行方自填
};
```

`consolidation` 沿用 v1 的字段与语义（第四周已在用），**不改名也不归一**——三审证明它必须是独立的一维：W20 既教新技能（Magic e 概念）又是 C 段复习周，任何互斥枚举都表达不了。第二稿把它归一进 `instructionMode` 是错的。

### 字位与积木的对应

**一块积木 = 一个字位，不一定是一个字母。** `ai` `oa` `th` 都是一块。

- `SOUNDS` 的键是**字位 ID**，`grapheme` 字段是它实际的字符串。单字母字位两者相同。
- **同形多音用不同 ID**，不要靠重复键：`oo_short`（book）与 `oo_long`（moon）、`th_unvoiced`（thin）与 `th_voiced`（this）。课程方案 §5.3 的 W13 `oo oo` 与 W16 `th th` 指的就是这两对。
- **凡是承载字位集合的字段，一律是字位 ID 数组**，不是字符串：`wallLetters`、`rackG4`、`rackG5`、`newPatterns`。
  现状是无分隔字符串（`"satipnckehrmdgoulfb"`），**里程碑 2 必须一并迁移**——`ai` 在无分隔字符串里没有任何办法表示成一块积木。渲染时的显示文本由 `SOUNDS[id].grapheme` 取。
- **拆词一律走分词函数**，按已教字位集合枚举**全部完整解析**，不要按字符切。`rain` 拆成 `r` `ai` `n` 三块，不是四个字母；周检词"全是 3 个字母"这条也随之改成**三个字位**。

  **判定以完整解析集合的基数为准**：0 解报未知片段、恰好 1 解返回该解、多于 1 解报歧义。**最长匹配只允许作为搜索剪枝，不得改变解析集合**——把"最长匹配"写成算法本身，实现者会做出贪心分词，同一个词在浏览器与 Node 两端得到不同结果。例：已教字位为 `a`/`ab`/`bc`/`c` 时，`abc` 有 `ab|c` 与 `a|bc` 两个完整解，属多解必须失败，不得由最长匹配任选 `ab|c`。
- **什么时候必须写 `W[词].segments`：两类，不止同形多音。** 只要一个词能枚举出多于一个完整解析，就必须逐词显式消歧，在 `W[词].segments` 里写死字位序列。触发多解的情形有两类，**第二类最容易被漏掉**：

  **第一类·同形多音**：自动分词只认得出字形 `oo`，认不出这个 `oo` 是 `book` 的短音还是 `moon` 的长音（`oo_short` 与 `oo_long` 并存时，`book` 会枚举出两个完整解而直接报歧义）。写成 `book: {segments:['b','oo_short','k']}`。

  **第二类·多字母字位与能拼出同一字形的更短字位并存**（2026-09-09 补·里程碑 2 实测）：当一个多字母字位的字形，**也能由若干已教的更短字位拼出来**时，所有含该字形的词都会枚举出多于一个完整解，**全部都要写 `segments`**。例：`ai` 与 `a`、`i` 并存时，`rain` 同时有 `r|ai|n` 与 `r|a|i|n` 两个完整解 —— **两个都合法，算法无从判断该取哪个**，必须由数据显式指定 `rain: {segments:['r','ai','n']}`。

  ⚠️ **这不是"新教那一周"专有的义务，是从教会那个字位起长期存在的义务。** `ai` 在 W5 教过之后，W6、W7 乃至第 40 周里凡是含 `ai` 的词，照样两解、照样要写 `segments`。**按"本周新教了什么"去走查是错的**，那会让 W6 起的每一周都漏掉此前各周教过的多字母字位。

  **判断方法：唯一权威判据是「枚举完整解析、数它有几个」**（2026-09-09 外部审查判 critical 后重写）：

  > **对共享词消费抽取器给出的每一个规范化词，直接调用同一个分词核心求出全部完整解析：**
  > **0 解 → 未知片段，按未知词规则处理，不要求 `segments`；恰好 1 解 → 自动分词即可，不需要 `segments`；多于 1 解 → 必须写 `segments`。**

  这条与本节前面「判定以完整解析集合的基数为准」是同一条规则，只是换到「数据该怎么写」的角度说一遍。**处理顺序固定：先求完整解析集合，再按基数分档** —— 零解优先于多解判定，避免对「含某个字形但整体根本拼不出来」的词误要求 `segments`（例如认读词、句子里尚未教的词）。

  ⚠️ **不要用「哪些字形有歧义风险」这类字形扫描当作完备判据。** v2.0 的 2026-09-09 早先版本写过一套四步法（「找出能被更短字位拼出的多字母字形，再看词里含不含它」），**外部审查证明它会漏判**，反例正是本规范 §3 自己给出的那个：

  > 字位集合为 `a`、`ab`、`bc`、`c` 时，`abc` 有 `ab|c` 与 `a|bc` **两个完整解**，必须写 `segments`。但 `ab` 拼不出（集合里没有 `b`），`bc` 也拼不出，**四步法算出的「风险字形集合」是空的，于是判定 `abc` 不需要 `segments`** —— 漏判。（已实测复现：分词核心对该集合下的 `abc` 正确抛 `segment-ambiguous`，而四步法判它安全。）

  **重叠型歧义**（两个字位的字形首尾交错）根本不需要「谁能拼出谁」，所以任何基于子串或可拆性的扫描都不完备。**字形扫描只能当预筛优化用**（先缩小要跑分词的候选集，省点时间），**不能决定一个词要不要写 `segments`**。

  **比对的是各字位的 `grapheme`（字形）不是字位 ID** —— `oo_short` 的 ID 与字形不同，按 ID 比会漏。但这只影响预筛，最终仍以分词核心的解析基数为准。

  **量级**：W5 教 `ai` 起，含 `ai` 的词每周都要写；后续 `th` `sh` `ee` `oa` `igh` 等字位逐一累加，到第二年是每周几十个词。

  **工具**：`tools/gen_segments.py`（**里程碑 2 交付物，落地前本条只描述预期行为**）跑一遍分词，对多解词按 **"选字位数最少的解"**（等价于优先用最长字位）生成 `segments` 建议，字位数最少的解不唯一时**报错让人决定**；**人只需复核 diff**，不要手写。生成后仍须过下面的一致性校验。

  > **示例词不等于词表。** 上面拿 `rain` 举例只为说明机制；某一周实际要写 `segments` 的词，按上面「枚举完整解析、数它有几个」的判据逐词求出，**词表本身见课程方案 §5.3**。特别注意反例：`chair` 的 `ch` 到 W15 才教、`air` 是第二年才列的独立映射且读音与 `ai` 不同 —— 这类词在 W5 根本拆不出，不属于本条的适用范围。
  **自动分词只用于无歧义的词；出现多解而 `segments` 缺失时，校验器必须失败并指出该词需要消歧**，绝不能按对象键顺序任选一个——那会让分词结果随实现变化，多条规则互相矛盾。

  **`segments` 自身的校验语义一并写死**（不写死则不同实现会接受与词形对不上的分段）：必须是**非空**的字位 ID 数组；每个元素必须是 `SOUNDS` 的**自有键**（不走原型链）；按 `SOUNDS[id].grapheme` 依次拼接后必须与**规范化后的词形完全一致**；`displayOnWall:false` 只影响墙展示，**不影响分词资格**。提供 `segments` 时以它为唯一解析结果，但上述一致性校验**照常执行、不得跳过**；缺失时才按完整解析集合的基数判 0 解 / 唯一解 / 多解。四类失败（非数组或空数组、ID 不存在、拼接结果不等于词形、元素非字符串）各配一个 fixture。

> **本节依赖里程碑 2（双字母字位）。** 里程碑 2 的实现范围因此包含四部分：引擎拆词、点亮墙与四个游戏、上述四个字段的类型迁移、以及 `check_data.js` 里全部逐字符逻辑（现有 6 处：第 60 行 `w[0]`、127 行 `w.length`、133 行 `[...w]`、139 行 `split('')`、140 行逐字符 `canSpell`、173 行最小对立比较）改用同一个分词函数。

### 点亮墙与首教日：唯一模型

**一个字段一个语义，不随周型跳变**（三审要求）：

| 字段 | 语义 | 取值 |
|---|---|---|
| `wallLetters` | 墙上**完整**的积木集合，**有序** | 等于 `SOUNDS` 全部键（除非显式标了 `displayOnWall:false`），按教学顺序排列 |
| `newPatterns` | 本周**新点亮**的积木 | 教新字位的周非空，否则空数组 |
| `FIRST_TEACH_DAY` | **本周**首教日 | 键集合恒等于 `newPatterns`；每个键的值那天的 `DAYS[].sounds` 必须含它。历史首教日不在本周文件里重复 |

**`audioKey` 不决定上墙资格。** 它只是"这块积木的录音去哪个键取"，是录音解析键，与展示无关。第二周的 `c` 和 `k` 发同一个音、共享录音，但它们是**两块不同的积木**，孩子两个都要认识——实测 `week02` 的 `wallLetters` 就是 `"ckehrmd"`，c 与 k 都在墙上。

所以：**凡是有独立字位 ID 与 `grapheme` 的记录一律上墙。** 第五稿写过"带 `audioKey` 的别名不上墙"，那条会让 `k` 从墙上消失，与实作和教学都相反，已撤回。将来若真有纯内部、不该展示的记录，用显式的 `displayOnWall:false` 表示，不要靠 `audioKey` 推断。fixture 要含 c/k 正例：两个 ID 都上墙、共享一份录音。

**墙的顺序有教学意义**（按合成拼读分组顺序点亮，不是字母表顺序），所以 `wallLetters` 是**数组不是集合**，顺序即展示顺序，不依赖对象键的枚举顺序。

**这是对现有实作的改动，属里程碑 2 的迁移范围**：实测 week01 `wallLetters="satipn"`（本周新）、week04 `="satipnckehrmdgoulfb"`（全集）——现状确实按周型跳变，第三稿只是如实描述了它。统一之后墙的"哪些是本周新点亮的"由 `newPatterns` 表达，渲染层据此做点亮动画。

现行校验器的 `META.consolidation || FIRST_TEACH_DAY[c] != null` 是旧模型，`DATA-WALL-01` 因此标「待实现」。将来 `wallLetters` 可以直接由 `SOUNDS` 推导而删除该字段，本版先固定语义不删字段。

`W` 的三个可选字段供 `PED-NOVELTY-*` 与分词使用，**不靠算法猜**：`lemma` 写词的原形（`rugs` → `rug`），只在自动去屈折规则覆盖不到时写；`proper: true` 标专有名词，专名不计入陌生词统计；`segments` 见上「字位与积木的对应」。

### `BOOK` 的两种结构

```js
// bookMode:'new'   —— 有正文的小书。复读周也是这一种，见下
BOOK = { title, zh, pages:[{line, art, zh}], rereadSources?:[{week, bookId}] }
// bookMode:'none'  —— 本周无小书
BOOK = null
```

**只有这两个取值。** 第四稿写过一个 `reread` 结构（`{sourceWeek, sourceBookId}`），那是我凭空设计的、**仓库里从来没有过实例**：第四周复读三本小书，实际做法是 `BOOK = { title:'Three Little Books', zh:'前三本小书复习', pages:[…] }`——用 `new` 的结构手工组了一本三合一的合集，而不是引用旧书。规范照实作走，删掉那个结构。

复读合集用可选的 `rereadSources` 标注来源，**它只供陌生度规则识别"这些正文是旧的"，不参与渲染**。课程方案 §5.3 的复读周可能要复读多本（W4 就是三本），所以它是数组。

**但自报的标签不能被无条件信任**——否则新写的正文套上 `rereadSources` 就能绕过小书新词上限。所以：

- 来源写到**页一级**：`pages[].source = {week, page}`，而不是只在书一级标注。
- 校验器按 `{week, page}` 取历史那一页的 `line`，**归一化后必须与本页逐词一致**；不一致就是改写页。
- **改写页按本周新正文计算新词**，不因合集级标注整体豁免。
- 每个来源必须满足 `1 <= week < META.week` 且可解析；`rereadSources` 要么缺省，要么非空且去重；普通新书**不许**填这个字段。
- 历史周的书目前没有稳定 `bookId`，所以来源用 `{week, page}` 定位。将来给 `BOOK` 加稳定 ID 后可换成 `{week, bookId, page}`。
- fixture：合法三书合集、悬空来源、正文不一致、重复来源、普通新书误填各一个。

`none` 时 `BOOK` 必须为 `null`，**禁止出现 `pages`**；`new` 必须有 `pages` 且每页三个字段齐。外部读物（牛津树、可解码读物）由 `externalReading` 表示，**不进 `BOOK`**——课件不承载别人出版的正文。

> **现有校验器不认 `none` 分支**：`check_data.js` 第 80 行是无条件的 `for (const p of BOOK.pages)`，喂给它 `null` 会直接抛异常退出，而不是给出可读的契约错误。所有 `BOOK` 访问都要先按 `bookMode` 分支——这条并入 `DATA-BOOK-01` 的实现范围，两种分支加"`rereadSources` 指向不存在的书"各要一个 fixture。

### `SOUNDS` 单条

```js
ai:{grapheme:'ai', ipa:'/eɪ/', type:'v', art:'<插画键>', mem:'一句话助记，带动作',
   cue:'动作口令，讲给孩子听，可嵌 <span class="en">ai、ai、ai</span>',
   challenge:'实验名，四个字以内', try:'实验动作，家长带着做',
   pass:'成功标准，家长据此判断过没过',
   how:'发音原理（家长折叠区）', warn:'最容易错（家长折叠区）',
   demo:[['词','中文'],['词','中文'],['词','中文']]},
```

- `type`：`'c'` 辅音 / `'v'` 元音。
- `art`：插画键，用英文小写单词（如 `guitar`），后面会照这个键去生成图。
- `grapheme`：**必需**，这个字位实际的字符串，也是**唯一的字形显示字段**——渲染一律取它，不得另设第二个字形字段。同形多音的两条 `grapheme` 相同、ID 不同。

  > **迁移要求（里程碑 2）**：v1.x 的示例与常量表里另有一个 `L` 字段，与 `grapheme` 重复且从未被解释。里程碑 2 的 `L` → `grapheme` 收敛步骤删除四周数据、两处 `Object.assign` 派生与两个 fixture 里的 `L`；此后 `SOUNDS` 条目**不得再出现自有键 `L`**。
- 一音多形（同一个音由不同字位表示）要建别名键并标 `audioKey`（第二周 `c`/`k` 的写法，照抄）；`audioKey` 必须指向 `SOUNDS` 里真实存在的另一个键。

## 4. 硬约束

### 4.1 校验器会查的

> **状态列怎么读**（2026-09-09 补，同日按外部审查改写：原写「已实现的规则任何时候都生效」与开头「门槛 A 前不构成任何一周的交付门槛」自相矛盾）。
>
> **把两件事分开说**——它们不是一回事：
>
> | | **校验器会不会跑它** | **能不能据它打回交付** |
> |---|---|---|
> | 标「已实现」的规则 | **会跑**，任何时候 | **门槛 A 之前：不能**，只作诊断信号；**门槛 A 之后：能** |
> | 标「部分实现」「待实现」的规则 | 未落地的部分跑不了 | **门槛 A 之前后都不能**，由 Claude 主审兜底（§4.2 与 §5） |
>
> 也就是说：**门槛 A 之前，本规范的任何一条都不构成交付拒绝依据**，校验器的红只是提示；**门槛 A 之后，已实现的规则成为交接门槛**，未实现的仍不作打回理由。等 **门槛 B** 全面 active 时本表应已无「待实现」「部分实现」，这条读法自然失效。三方分工里的「门槛 A 下未实现规则不作打回理由」引用的就是这个定义。
>
> ⚠️ **「部分实现」必须自己写清边界**（外部审查 high）：只标「部分实现」而不说哪部分已生效，执行方仍然无法判断自己要对什么负责——整行免责的粒度太粗。**每个标「部分实现」的条目都要在备注里列出「已生效子项 / 未实现子项」**，或者干脆拆成两条独立规则。**在这件事做完之前，门槛 A 的 A6 不算满足**（见 §8）。

**「状态」列是这份规范最重要的一列。** 标「待实现」「部分实现」的条目现在不会拦住相应的错误——把它写成已生效，就是拿没做的事当门槛，第四周正是这么绿着交出去的。

三条纪律：

1. 每条待实现的都要配一个**故意写错的 fixture**，证明它真的会红，才允许改状态。
2. **状态变更、校验器代码、正反 fixture 必须在同一个 commit 里**，不许分开。
3. 校验器的错误信息和 fixture 文件名都用这里的规则 ID，防止文档与实现再次漂移。

#### `PED-NOVELTY-01` · 陌生词目标

第四周的教训：技能重点写着「陌生 CVC」，全周 20 个练习词却全在前三周词典，0 个新词，校验器全绿——因为它只查"字位在不在已教范围"，从不问"这个词孩子见没见过"。

**两套词集必须分开，这是复审点名的关键**：

先建**一个共享的曝光词抽取器**，两套词集都从它派生——三审指出用"包含清单"迟早漏字段，所以改成**默认全收、显式排除**：

**曝光词抽取器**：每种块在 schema 里声明自己的**可见文本路径**（例如 `blend` 是 `words[]`、`sentences` 是 `items[][0]`、`note` 是 `html`），抽取器按声明取词。非块对象同样逐项列出可见字段：`BOOK.pages[].line`（按 `bookMode` 分支）、`G1_ROUNDS[].pos/neg`、`G1_THEME[].cmd`、`G4_WORDS`、`G5_WHITELIST`、`WALL_HINT[].en/say`、`SOUNDS[].demo[][0]`。

**不要递归收集所有字符串**——那会把中文说明里夹的英文、插画键、存储键一起收进来。**新增块类型没有抽取声明时直接失败**（`DATA-BLOCK-01`），这样漏字段会变成红灯而不是假绿。

**排除分两层，不要用一张表承担两种语义**（四审要求）：

| 排除项 | 曝光层（孩子见没见过） | 统计层（算不算陌生真词） | 理由 |
|---|---|---|---|
| 家长折叠区字段（`how`、`warn`） | **排除** | 排除 | 家长看的，孩子不读 |
| `RESERVED` 与全部测评池 | **排除** | 排除 | 本来就不许出现在别处 |
| 认读词（`sight` 累计集合） | **算曝光** | 排除 | 孩子确实见过，但它们不按规则拼，不作为解码陌生度的统计对象 |
| 标了 `W[词].proper` 的专名 | 算曝光 | 排除 | 见过，但不参与解码统计 |
| G1 干扰词 | 算曝光 | 排除 | 只听不读 |

「功能词」与「认读词」**不是同义词**：认读词是 `sight` 块声明的那批；`the`、`and` 这类若已按规则可解码并进了教学块，就照普通教学词处理，不额外排除。

集合推导是**两阶段流水线**，每阶段有名字、有审计输出，不靠"内容词"这类自然语言词性判断：

```
① visibleExposureTokens(week)   = 抽取器取到的全部 token − 曝光层排除
② statisticalContentTypes(week) = ① 的归一化词种 − 统计层排除
```

| 集合 | 定义 | 用途 |
|---|---|---|
| **本周目标教学词** | `②(本周)` 里，来源是 `blend`、`flash` 的 `k:'w'` 项、`wordforge`、`sentences` 的那部分 | 算本周"教了哪些词" |
| **历史曝光词** | `①(第 1 周) ∪ … ∪ ①(第 N-1 周)` 的归一化词种 | 算"孩子见没见过" |

"**内容词**"在本文里是 `statisticalContentTypes` 的成员，没有别的含义——即"归一化 token 减去认读词、专名、G1 干扰词与测评池"。审计输出要同时列出：原始位置、归一化后的 lemma、曝光层结果、统计层被排除的理由。

**陌生判定 = 本周目标教学词 − 历史曝光词。** 用同一套集合既算本周新词又算历史，会让孩子在 G5 里玩过的词下周被判成"陌生词"——测评于是继续偏向记忆。

规则由 `META.noveltyPolicy` 驱动，**该字段来自课程配置，不由执行方自己填**：

```js
noveltyPolicy: {
  realWordTarget: 12,       // 至少多少个不同的、历史未曝光的真词
  pseudoWordTarget: 0,      // 假词目标（W36 这类解码大练用）
  minTeachingDays: 3,       // 这些词至少分布在几天
  minActivityKinds: 2,      // 至少出现在几种教学活动里
  assessmentMaxHistoricalTypeRatio: 0,  // 测评短文允许的历史词比例上限（按不同词计）
  bookMaxNovelTypes: 5,     // 教学小书允许的新词种数上限
}
```

**归一化口径**（不钉死就会靠改写形式绕过）：

1. **token 化**：按 `[A-Za-z]` 连续段切词；词内撇号（`don't`）与连字符（`sun-hat`）**先按分隔符切开再各自计入**；数字与其他非字母字符直接丢弃。
2. **大小写**：一律转小写后比较。句首大写、全大写标题都归一。
3. **去屈折**：只覆盖课程实际教的那几种（`-s`/`-es`、`-ing`、`-ed`），含双写还原与去 e 还原（`running`→`run`、`making`→`make`）。
4. **兜底**：上面覆盖不到的写 `W[词].lemma` 显式声明；专名写 `W[词].proper`，不靠词表猜。
5. **认读词**的来源是 `sight` 块的累计集合，机器可读，不另维护词表；它在两层里的处置见上表。

抽取器要能**输出可审计的词种清单及每个词被排除的理由**，否则规则出错时无法定位。历史范围只到第 N-1 周，缺周或重复周直接失败。

逐周表里凡目标是迁移、探针或模拟测评的周，都要审定这份策略——**不要按周号硬编码**。第一年已知需要的至少有 W4（陌生 CVC）与 W36（陌生词解码大练）；**课程配置补齐全部这类周之前，§8 第 4 条不算满足**。

#### `PED-NOVELTY-02` · 复现率

**测评短文和教学小书方向相反，分开定义**：

- **测评短文**（`ASSESS_TEXT`）：内容词与历史曝光词的重合比例不得超过 `assessmentMaxHistoricalTypeRatio`（默认 0，即完全隔离）。第四周 7 个内容词里 4 个前三周教过，其中 rug、rub 还是短文里重复最多的——那测的是记忆不是解码。
- **教学小书**（`BOOK`）：反过来要**足够多的复现**才读得动，规定的是新词种数上限 `bookMaxNovelTypes`，不是陌生度下限。

两者都按**归一化后的不同内容词**计算，不按 token 计。内容词抽取与上一条同口径。

#### `DATA-PHASE-01` · 阶段字段

第四周 D7 的造词工坊排在周检前却标着"测后可选"，家长照着做就先玩了再测。

**用结构字段表达，不靠标题里的字眼判断**——靠文案措辞的检测，改个标题就绕过去了：

```js
{ t:'造词工坊', phase:'post-assessment', optional:true, blocks:[...] }
```

校验 `phase` 在一天之内单调递增（`pre-assessment` → `assessment` → `post-assessment`），且所有 `post-assessment` 步骤严格排在**当天最后一个「测评」类别块**之后。「测评」类别取 §3 块类型表的类别列，规则正文不再手列块名——两处各列一份迟早对不上。

`baseline` 虽然归在「测评」类别里，但它只是**成绩摘要的展示**，不是要先完成的测评动作，所以**不计入 `post-assessment` 的判定基准**。实现时它单独标一个 `display-only` 标记。

#### `DATA-RACK-02` · 积木架容量

v1.0 §2 提过但没落成规则的一条：G5 造词积木架第一周 12 块、第二周 13 块、第三周 19 块，一路加下去对七岁孩子会越来越难找。

给 `rackG4` / `rackG5` 定最大块数与分组规则，超出就得按题库收窄或分组，不能默默变长。**具体上限值待定**——里程碑 0 定过第三周的分组固定位方案，要先对照那个方案再拍数；定下来时要给"刚好等于上限"和"超出一块"两个 fixture。

#### 累计教学词典从哪来

**不能信执行方自报的历史。** 独立文件模式下填个空数组就能让陌生度规则全绿。

- **仓库模式**（正常情况）：校验器按 `project.json` 的 `weeks` 顺序加载第 1 到 N-1 周的数据层，现算，不读 `META`。
- **独立文件模式**：必须随文件附一份 history manifest，由**主机从受信任的提交生成**，含哈希算法、规范化序列化方式、覆盖的文件集合与版本字段。校验器要能验证它的来源（仓库内固定公钥签名、HMAC，或主机给的不可编辑基线），**只有内容哈希是不够的——能改文件的人也能改哈希**。版本不匹配即失败；清单被篡改要有失败 fixture。
- **拿不到可信历史时**：明确降级为「不判定陌生度」并**返回失败**，不是放行。

#### 每天四类块

规则 ID `DATA-DAY-CATEGORIES-01`。第 1 到第 6 天，每天必须有**拼读、阅读、输出、打卡**四类各至少一块；**第 7 天不适用**（周检日，`rest:true`）。类别按 §3 块类型表的"类别"列判定，不按步骤名。这是"每天 1–2 个新音"的唯一例外，八条铁律不变。

**与当前实作的差距**（迁移时一并处理）：`assessment_contract.js:42` 只在 `consolidation` 周检查这四类，且「输出」只认 `output` 一种块、「阅读」只认 `book`/`sentences`。要扩到所有周、并把实际承载输出活动的 `g1`/`g4`/`g5`/`pair`/`wordforge`/`initialpick` 纳入「输出」。

**并且 `output` 块自己不能单独满足「输出」类别**：它渲染出来只是一段 `pnote` 样式的家长指引文字，不是孩子的产出活动。规则应为——当天有 `output` 块时，同一天必须另有至少一个真实输出活动块。否则"输出"这一类会被一段说明文字糊弄过去。fixture 要覆盖 `phoneme`/`skill`/`none` 三种 `teachingMode` 各缺一类的情况。

## 6. 常见会被打回的错

| 错法 | 后果 | 来源 |
|---|---|---|
| 周检词顺手写进了某个 `note` 的举例里 | 铁律 3 破功，孩子周检前就见过了 | 第二周 |
| 裸读步骤用了 `words` 块 | 图片先于拼读出现，测的是认图不是解码 | 第二周 |
| 某天分钟数加起来 29 或 31 | 校验器直接报错 | 第二周 |
| `G5_WHITELIST` 里混进含重复字位的词（如 `dad`） | 积木架每字位 1 块，摆不出来 | 第二周 |
| 四音词只给"从后往前接"一种教法 | 词尾辅音群用这个方法更卡 | 第二周 |
| `SOUNDS` 整体替换掉旧音 | 快闪复习、G3 词对、G5 白名单大面积报错 | 第二周 |
| 发明了新的块类型 | 引擎不认识，渲染成空白 | 第二周 |
| **技能重点写着"陌生词"，练习词却全是教过的** | 校验器全绿但教学目标没达成 | **第四周** |
| **测评短文的内容词在前几周教过** | 测的是记忆不是解码 | **第四周** |
| **"测后可选"的块排在周检之前** | 家长照着做会先玩再测 | **第四周** |
| **把双字母字位当两个字符处理** | 拆词、点亮墙、四个游戏、周检词长度判断全错 | 首审 |
| **同形多音用重复的对象键**（两个 `oo`） | 后一个覆盖前一个，短音 oo 直接消失 | 首审 |
| **用无分隔字符串承载字位集合** | `ai` 没有任何办法表示成一块积木 | 复审 |
| **只用一套词集算陌生度** | 孩子在游戏里玩过的词下周被判成"陌生词" | 复审 |
| **外部读物写进 `BOOK`** | 课件承载了别人出版的正文 | 复审 |
| **用一个互斥枚举描述混合周** | W20 既教新概念又是复习周，塞进单一枚举后无论选哪个都违反另一半课程语义 | 三审 |
| **同一个字段按周型改变语义** | `wallLetters` 时而是本周新字位、时而是全集，读它的人和代码都得先判周型 | 三审 |
| **块类型表照抄旧版不与渲染层对齐** | 六个在用的块（`initialpick`/`retest`/`probe`/`output`/`assessment`/`baseline`）曾长期不在表里，表却写着"只能用这些" | 三审自查 |

## 7. 你写完之后的流程

对应三方分工规范 §3 的九步流转：

1. 自己跑 `python tools/project.py build` 与 `check --quick`——不过就改到过为止
2. 确认 `git status` 只有本周 `weekNN.data.js` 与允许的派生物，按白名单提交推送
3. 主机 `pull` 并核对提交范围
4. **人过一遍教学法**——§4.2 那五条、§5 那份清单，校验器查不了
5. 音频清单扩写、插画提示词、出图与注入
6. 完整 `python tools/project.py check` + codex 审 → critical 与 high 为 0 才定稿

第 4 步是这份规范存在的理由：**能写成规则的都搬进了 §4.1 交给机器，剩下的才是人要看的。** 哪天第 4 步又抓出机器本可以抓的东西，回来补 §4.1，别只在当周改数据。

## 8. 这份规范什么时候生效

首审（归档 43）与复审（归档 44）都判定：草案不能作为第六周的交接契约。

**两个门槛，不是一个**（2026-09-09 用户拍板拆分）。原先只有一条「全部满足才 active」的线，而它被条件 3（§4.1 表里不再有「待实现」「部分实现」）与条件 2 的里程碑 2b（截止 2026-10-31）钉在 10-31 之后 —— 但 **W6 审定截止 10-04、开课 10-05**，三方分工又写着「阶段 B 最早第六周」。这条链在拆分前不可达：规范永远赶不上它自己承诺的第一次交接。拆分把「够不够 W6 用」与「够不够全面 active」分开判。

### 门槛 A：W6 交接可用（解除「尚不构成第六周交接依据」）

满足 A 的**全部**条件后，本规范即可作为**第六周及其后各周的交接依据**，状态记为「**部分生效·限交接**」。此时未实现的规则不得作为打回理由，执行方只对已实现的规则负责。

- **A1** 里程碑 2 落地（内容同下方 B1），且 §4.1 中里程碑 2 范围内的规则均已从「待实现」「部分实现」转为「已实现」。**范围不含测评部分——那一块单独由 A2 拥有**（2026-09-09 按外部审查拆清归属，避免 A1/A2 读起来像两份重叠的范围）
- **A2**（测评部分，A1 不含）`DATA-ASSESS-01` 的**里程碑 2 段**（最小路由）落地，**W5 fixture 通过**。**2b 的完整矩阵不属于门槛 A**
- **A3** `noveltyPolicy` 的逐周取值由课程配置给出，且覆盖全部迁移、探针与模拟测评周
- **A4** 三方分工升 v1.2 并完成一次副机 dry run，**dry run 结果作为激活证据**
- **A5** 第五周由 Claude 按本规范做完一轮，规范里被这一轮证伪的地方回改。**闭环判据**（2026-09-09 外部审查补，原写法无法判定何时算完）：这一轮发现的每一项**要么有关闭记录（已回改，附提交号），要么有书面接受（明确决定不改，附理由）**；不存在既未回改也未书面接受的悬空项
- **A6** §4.1 表里仍标「待实现」「部分实现」的条目，其**免责口径要写明**，让执行方一眼看得出自己不用负责哪些。
  ⚠️ **本条尚未满足**（2026-09-09 外部审查判 high，推翻了同日早些时候「已由表头总注满足」的判定）：表头总注只能按**整行**免责，而标「部分实现」的规则**行内既有已生效的子项也有没落地的子项**，执行方照样分不清自己要对什么负责。**满足判据**：§4.1 里**每一个**标「部分实现」的条目都列出「已生效子项 / 未实现子项」（附对应的代码入口或规则编号），或拆成独立规则；此后本条才算完成。表头总注是必要不充分条件

**门槛 A 下 W6 的额外保护照旧执行**：第六周交付仍由 Claude 主审教学法（§4.2 五条 + §5 清单），安全模式退路不变，见下「W6 首次交接的退路」。

⚠️ **谁来宣布门槛 A 达成、凭什么宣布**（2026-09-09 外部审查补：原文只列条件、没规定裁定流程，主副机可能对「阶段是否已切换」理解不同）：

- **唯一裁定人 = 用户**。Claude 负责核对 A1—A6 并给出证据，**但切换阶段由用户拍板**，不由任何一方自行判定。
- **必须留一份版本化的激活记录**（写进本仓库 `docs/`，不是口头结论），至少含：本规范的提交号、里程碑 2 的提交号、W5 的验收结果、**副机 dry run 的证据路径**、**此刻仍标「待实现／部分实现」的规则清单**（即执行方不用负责的那批）、生效时间。
- **该记录提交之后，阶段 B 才开始**。记录不存在 = 门槛 A 未达成，无论条件看起来满足与否。

| 门槛 A 的条件 | 对应门槛 B 的哪一条 |

所以准确的说法是：**A 在能力要求上弱于 B**（A1/A2 各取 B 对应条的一部分，A3/A4/A5 与 B 相同），另加一条 B 不需要的过渡期义务 A6。**B 比 A 多要求的是两件**：B2 的**里程碑 2b 完整矩阵**（截止 2026-10-31）与 B3 的**§4.1 整表清零**。

第 6 步不是形式。规范没被人完整执行过一次，不知道它是否可执行——第五周正好是那一次。

### 为什么止于第六稿

五轮审查的数量曲线：19（3C/6H）→ 27（1C/8H）→ 14（1C/6H）→ 12（0C/5H）→ 11（0C/5H）。critical 连续两轮归零，**high 停在 5 不再下降**，而且每轮 high 的性质都一样——**规范与实作不符**，且都是把代码读得更细才发现的：

| 轮次 | 发现 |
|---|---|
| 三审 | `rackG4` 是无分隔字符串；`BOOK` 新分支会让校验器抛异常 |
| 四审 | `reread` 结构仓库里从没有过实例；`W` 会裁剪（125 → 56）不是历史账本 |
| 五审 | `audioKey` 不决定上墙（实测 c 与 k 都在墙上）；W5 fixture 与本文自己的矩阵冲突 |

规则表 23 条里 22 条标着「部分实现」或「待实现」——**这份规范描述的东西 95% 还不存在**。继续在文档层面推敲的边际收益已经很低：剩下的缝要靠写实现和 fixture 时才能真正暴露。

所以 2026-09-08 拍板：**定为草案，转去做里程碑 2**。上面六条生效条件就是实现时的验证清单；每条实现完回来改一次状态列，改到 §4.1 没有「部分实现」「待实现」为止。

### W6 首次交接的退路（2026-09-08 拍板采纳）

1. 第六周交付**仍由 Claude 主审**教学法（§4.2 五条 + §5 清单），不因为规范生效就省掉这一步。
