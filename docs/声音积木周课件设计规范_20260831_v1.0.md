# 声音积木 · 周课件设计规范 v1.0

**用途**：拿到这份文档 + 上一周的定稿 HTML，任何人或任何模型都能独立做出下一周的课件，不需要回读会话历史。

**真相源优先级**：上一周定稿 HTML 的实作 > 本规范 > 会话记忆。三者冲突时以实作为准，并回来修订本规范。

**已落地实例**：第一周 `week01-v3.html`（本规范的抽象来源）、第二周 `week02.html`（本规范的第一次验证）。

**修订**：2026-08-31 v1.0 首次固化，抽自第一周定稿 + 第二周移植过程。

---

## 0. 产品定位

- **使用者**：7 岁孩子 + 陪学家长，两人共用一台手机或平板，近距离共读。孩子看主线，家长看折叠区。
- **交付物**：每周一个单 HTML 文件。家长双击打开，或直接微信发送，收到即可用。
- **课程总长**：40 周。每周 7 天，前 6 天各 30 分钟，第 7 天休息 + 游戏 + 周检。
- **教学法**：合成拼读（synthetic phonics）。字母音 → 逐音合体 → 解码真词 → 第 6 天独立读完一本小书。
- **不做的事**：不做外教对话、不做单词量竞赛、不做无法当场验证的"磨耳朵"。每一样学的东西都要能当场测。

## 1. 铁律（违反即返工）

| # | 铁律 | 为什么 |
|---|---|---|
| 1 | **合成语音（TTS）绝不读单个音素** | TTS 会把 /t/ 读成字母名 "tee" 或加元音尾巴"特"，这恰好是整套方案唯一会让孩子永远拼不出词的技术点。音素只能用真人录音或家长按动作口令示范。 |
| 2 | **单文件全内嵌，零外部依赖** | 字体、图片、音频一律 base64 内嵌。出现任何 `src="assets/..."` 相对路径就是 bug——家长收到的是一个孤立文件，不是一个项目目录。 |
| 3 | **周检词必须从未在本周任何地方出现过** | 周检测的是解码能力，不是记忆。靠 `RESERVED` 常量 + `Guard.isReserved()` 运行层双重拦截，不靠"我检查过了"。 |
| 4 | **图片不得先于拼读出现** | 词卡插图是"拼完之后核对"，不是"看图猜词"。裸读 / 闪读环节必须用 `flash` 块（纯文字），绝不能用 `words` 块（带图）。 |
| 5 | **元音红 / 辅音青 的语义色跨周不变** | 这是要让孩子自己发现的规律（"每个词里都得有一块红的"）。它是教学内容，不是装饰，不能跟着周主题色走。 |
| 6 | **每个游戏必须有回合上限 + 结算 + 状态落盘** | 不结算的游戏等于没有尺子，家长不知道孩子到底会不会。 |
| 7 | **每天都要有可当场验证的打卡项** | 打卡清单 + 周检是家长唯一的尺子。没有尺子，家长只能靠感觉，方案就失效了。 |
| 8 | **新音素没有真人录音时，宁可不给听音入口，也不用 TTS 顶替** | 见铁律 1。降级方式是把听音按钮换成"家长按下面的口令示范"，不是让按钮变哑巴。 |

## 2. 分发与工程形态

- **一个 HTML，无构建步骤**。没有打包器、没有 npm、没有框架。原生 DOM + 模板字符串。
- **体积参考**：第一周定稿 2.5 MB，其中约 80% 是内嵌图片，约 12% 是内嵌音频，字体子集约 62 KB，代码约 100 KB。
- **资产内嵌方式**：图片 `data:image/png;base64,...`；音频 `data:audio/mpeg;base64,...`；字体 `@font-face` + base64 woff2 子集。
- **注入锚**：单词音频由 `tools/build_audio.py` 注入，锚标记为 `/* WORD_AUDIO_INJECT_START */` … `/* WORD_AUDIO_INJECT_END */`，幂等可重跑。
- **`assets/` 目录是素材源和可重建缓存，不是交付物**。交付物只有那个 HTML。

## 3. 视觉设计系统

### 3.1 令牌三层 —— 换周只动第一层

**第一层 · 周主题色（每周更换，刻意制造新鲜感）**

| 令牌 | 作用 | 第一周（绿） | 第二周（紫） |
|---|---|---|---|
| `--ground` | 页面底色 | `#EEF1EE` | `#F1EFF7` |
| `--surface` | 卡片面 | `#FFFFFF` | `#FFFFFF` |
| `--surface-2` | 次级面 / 折叠区 | `#F6F9F5` | `#F8F6FC` |
| `--sunk` | 凹陷 / 未点亮态 | `#E4E9E4` | `#E7E2F1` |
| `--line` / `--line-2` | 分隔线 / 强分隔线 | `#DBE2DC` / `#C6D0C8` | `#DED8E9` / `#CBBBE3` |
| `--ink` / `--ink-2` / `--ink-3` | 文字三级（带一点周色相的中性色） | `#232B28` / `#5C6B65` / `#8A968F` | `#292633` / `#655F71` / `#8B8497` |
| `--tile-face` / `--tile-edge` | 积木面 / 积木边 | `#FFFFFF` / `#C9D3CB` | `#FFFFFF` / `#CFC7DE` |

换周规则：

- 换的是**色相**，不是明度关系。新一周的 `--ground` 明度必须落在与前几周同一档（浅色模式 L\* 约 93–95）。
- `--ink` 对 `--ground` 的对比度 ≥ 7:1；`--ink-2` ≥ 4.5:1；`--line` 要肉眼可见但不抢戏。
- 深色模式必须同步给一套（`--ground` L\* 约 10–12），且**两条路都要写**：`@media (prefers-color-scheme:dark)` 里用 `:root:not([data-theme="light"])` 包一层，再单独写 `:root[data-theme="dark"]`。只写一条会导致跟随系统或手动切换二者之一失效。
- 主题选择落盘到 `localStorage['soundblocks-theme']`，这个键**跨周共用**——家长在第一周选了深色，第二周打开就该还是深色。

**第二层 · 教学语义色（跨周冻结，永不更改）**

| 令牌 | 语义 | 浅色值 | 深色值 |
|---|---|---|---|
| `--vowel` | 元音积木 | `#D8492F` 砖红 | `#F0785E` |
| `--cons` | 辅音积木 | `#1C6675` 青 | `#5FB7C8` |
| `--accent` | 今天 / 里程碑 / 星标提示 | `#DE9420` 琥珀 | `#EDB055` |
| `--ok` | 完成 / 通过 / 打卡 | `#48874E` 绿 | `#72B978` |

每个语义色配一组 `-soft`（浅背景）和 `-line`（描边）。

> **选周主题色时必须避开这四个色相。** 第二周的紫 `#7457A6` 与琥珀 accent 距离足够，可用。若某周想用橙色系底色，必须先改 accent，否则"今天"角标和星标提示会消失在背景里。同理，红色系底色会和元音红打架，青色系底色会和辅音青打架——**留给周主题色的安全区其实是紫 / 蓝 / 靛 / 灰绿 / 赭这几档**。

**第三层 · 结构令牌（跨周冻结）**

- 圆角：`--r-s:8px` `--r-m:14px` `--r-l:22px` `--r-xl:30px`
- 阴影：`--shadow-1`（贴地）/ `--shadow-2`（悬浮）/ `--shadow-3`（抬起）
- 积木尺寸：默认 64×72，`--sm` 42×48，`--lg` 92×104。底边加粗（`border-bottom-width` 5/4/7px）模拟实体积木厚度，这是整套视觉的记忆点，不要改。

### 3.2 字体

| 变量 | 字体 | 用途 | 处理 |
|---|---|---|---|
| `--en` | Andika | 所有英文字母、单词、音标 | OFL 子集内嵌，含 IPA 补充切片（`U+026A` 等按 `unicode-range` 追加） |
| `--dis` | Baloo 2 | 标题、日卡标题、数字、按钮 | OFL 子集内嵌 |
| `--zh` | Noto Sans SC → Microsoft YaHei | 全部中文正文 | 不内嵌，走系统 |

Andika 是为儿童识字设计的字体（`a` `g` 是单层写法，和手写体一致），**不能换成通用无衬线字体**——孩子正在建立字形与音的映射，双层 `a` 会干扰。

### 3.3 组件清单

积木 `.tile`（含 `--v` / `--c` / `--sm` / `--lg` / `--wallon` / `--walloff`）、日卡 `.daycard`、步骤手风琴 `.step`、家长提示条 `.pnote`（四种 tone）、折叠区 `details.fold`、词卡 `.wcard`、音素实验室 `.soundlab`、合体器 `.blender`、小书 `.book`、闪卡 `.flash`、打卡清单 `.checks`、表格 `.table`、游戏容器（G1–G5 各一套）、庆祝覆盖层 `.celebrate` + 彩带、播放失败提示条 `#audioFailBar`。

## 4. 信息架构

### 4.1 首页（`renderHome`）

自上而下固定顺序：

1. **开课日期提示条**（仅当未设且未跳过时出现，可"设置"或"不用了"）
2. **hero**：周次眉标 → 大标题 → 一段"这周为什么这么排"的说明 → 积木点亮墙（本周音素积木，已学的点亮、未学的灰暗）
3. **本周七天**：7 张日卡，显示 完成态 / 今天角标 / 休息日虚线边
4. **词卡墙入口**：一个整块可点按钮，进二级页
5. **开课前，家长先做三件事**：4 个折叠区（校准发音 / 固定时间位置顺序 / 调整预期 / 关于发音功能）
6. **页脚**：一段"为什么这一周是这几个音"的说明 + 授权署名 + 开课日期修改入口

### 4.2 日视图（`renderDay`）

返回链接 → 日标题 + 本日新音积木 → 今日目标条 → 步骤手风琴（每步：序号 / 标题 / 分钟数 / 展开体）。

### 4.3 词卡墙（`renderWall`）

本周所有教学词的图文卡 + 战利品墙点亮态。词表来自 `taughtWords()`——只取 `DAYS` 里 `words` 块的词。

> **保留词（周检词）完全不上词卡墙。** `renderWall()` 用 `Guard.isReserved()` 过滤掉它们，墙上一个都看不到。
> 它们只在第 7 天**周检块**里以锁定卡（`pointer-events:none`）出现，不可点、不发音。
> 这条第一周和第二周实作一致——铁律 3 要求孩子在周检前从没见过这些词，让它们上墙就破功了。

### 5.3 缺素材守卫（第二周已全部落地，之后各周继承）

第一周因为素材齐全，多处直接下标取值没有兜底。第二周落地了一套守卫，**新一周只要素材未齐就靠它们降级，不用再改数据层**：

| 位置 | 守卫 | 缺素材时的表现 |
|---|---|---|
| 所有词卡 / 闪卡 / G1 释义 / G3 开门图 | `hasIll(key)` —— 判"图真的在不在"，不是"art 键写没写" | 降级成"单词 + 中文" |
| `sound` 块助记图 | `PHONEME_ILL[s.art] ? <img> : ''` | 只渲染文字助记 |
| 音素听音按钮 | `hasPhoneme(b.s) ? 按钮 : 家长示范提示` | 出现"这个音还没有真人录音，请按口令示范" |
| 字母积木 · **只承担发音**的（`tileHTML` / 首页点亮墙） | 无录音时**换元素**：`<button data-sayph>` → `<div role="img">`，class 与点亮态样式不变 | 静态积木，不留可聚焦可点却毫无反应的空壳 |
| 字母积木 · **另有行为**的（G4 / G5 积木架） | **保持 `<button>`**（点它要把字母摆进槽位），只是不挂 `data-sayph`、`aria-label` 改成"字母 x" | 仍可点、仍能摆词，只是不发音 |
| 打印小书插画 | `BOOK_IMG[pg.art] ? <img> : ''` | 省略插画，保留句子 |
| `bookArt()` | 回落 `ART[key] \|\| ''` | 空串，不输出 `undefined` |
| 庆祝主角图 | `CELEBRATE_NAT ? <img> : ''` | 只放彩带 |

> **关键点之一：降级是换形态，不是删属性。** 第二周踩过一次——首页点亮墙"没有录音就去掉 `data-sayph`"，
> 但元素仍然是 `<button>`，于是留下一排可聚焦、可点击、点了毫无反应的空壳，对触屏和读屏都是误导（违反铁律 8）。
> 正确写法是按能力**换元素**：有录音渲染 `<button>`，没有渲染 `<div role="img">`，样式和点亮态保持一致。
> 凡是"这个能力暂时没有"的地方，都要问一句：**去掉能力之后，这个元素还应该长成原来的样子吗？**

> **关键点之二：判图不判键。** `hasIll` 让 `art` 键可以先写好、图后补——GPT 把插画交回来内嵌进常量，页面自动点亮，数据层一个字都不用改。这是插画与代码解耦的关键。

### 5.4 数据结构定义

```js
// ⚠️ SOUNDS 的键必须是字母本身。tileHTML / G2 积木 / G4·G5 积木架都按
//    "字母即键"去查 SOUNDS[c]，键对不上会直接抛错。
//    一音两形（第二周的 c 和 k）要建别名键，两个键都得存在：
//      SOUNDS.c = { ..., audioKey:'c' }
//      SOUNDS.k = Object.assign({}, SOUNDS.c, { L:'k' });   // 连 audioKey 一起继承
//    并且 FIRST_TEACH_DAY 里两个字母都要有，那一天的 sounds 也写两个。
//
// ⚠️ audioKey 是必须的：录音按"音"存，不按"字母"存。/k/ 只有一段录音——
//    不标 audioKey 的话，补录音时写进 PHONEME_AUDIO.c 会让 c 点亮而 k 仍是静态
//    积木；写成两份又要重复几十 KB base64 且容易漏配其中一个。所有"有没有录音"
//    的判断和播放一律走 hasPhoneme(ch) / phAudioKey(ch)，不要直接查 PHONEME_AUDIO[ch]。
SOUNDS[键] = {
  L,          // 显示字母（别名键只换这一项）
  ipa,        // '/k/'
  type,       // 'c' 辅音 | 'v' 元音
  art,        // 助记插画键，无图传 null
  mem,        // 一句话助记："蛇在吐信子 sssss"
  cue,        // 动作口令，讲给孩子听
  challenge,  // 实验名："纸片起飞"
  try,        // 实验动作
  pass,       // 成功标准，家长据此判断
  how,        // 发音原理（家长折叠区）
  warn,       // 最容易错（家长折叠区）
  demo        // [[词, 中文]] 放进单词里听
}

W[词] = { zh, art }              // art 为插画键，无图传 null
BOOK   = { title, zh, pages:[{ line, art, zh }] }
DAYS[] = { n, wd, title, sounds:[], goal, rest?, steps:[{ t, min, blocks:[] }] }
```

## 6. 音频层规则

优先级链，从高到低：

1. **音素**：真人孤立音录音（`PHONEME_AUDIO`）。没有就降级为家长口令示范，**绝不用 TTS**。
2. **单词 / 句子**：内嵌 mp3（`WORD_AUDIO`）。没有就 TTS 兜底（`speechSynthesis`，`lang='en-US'`，`rate` 常速 0.75 / 慢速需低于常速）。
3. **播放仲裁**：所有播放走 `AudioBus`，切页、切游戏、切步骤时统一 `stopAll()`。音素之间允许叠音，音素会打断单词与 TTS。
4. **失败可见**：播放失败弹 `#audioFailBar` 提示条并提供重试，不能静默失败让家长以为是孩子没反应。
5. **保留词拦截**：`WORD_AUDIO` 取值前先过 `Guard.isReserved()`，防止周检词被点出声。

## 7. 教学法规则

### 7.1 音素排序

按合成拼读标准分组顺序，不按字母表：

- 第 1 周：`s a t i p n`
- 第 2 周：`c k e h r m d`
- 第 3 周：`g o u l f b`
- 之后：`ai j oa ie ee or` → `z w ng v oo oo` → `y x ch sh th th` → `qu ou oi ue er ar`

选这个顺序的理由要写进每周页脚：**这几个音能立刻组出真词，孩子第二天就能尝到"我自己读出来了"**。

### 7.2 每周节奏

| 天 | 安排 |
|---|---|
| 1–5 | 每天 1–2 个新音 + 拼读 + 一个游戏或听辨环节 + 打卡 |
| 6 | 小书日。目标是"独立读完整本"。若还有未教音素，最多安排 1 个，且必须在开读之前教完 |
| 7 | 不上新课。游戏任选 + 5 分钟周检 |

### 7.3 内容硬约束

- **词全部落在已教字母范围内**（听辨环节例外：只听不读的环节可以用含未教字母的词，但要在 `note` 里写明"只用耳朵听，不用读"）。
- **CVC 优先**。四音词（含连辅音）必须单独标为挑战，并且**按辅音群的位置选择拆法**——这两种拆法方向相反，用错会让孩子更卡：

  | 辅音群位置 | 例词 | 教法 |
  |---|---|---|
  | 在词首 | `snap` `spin`（第一周） | **从后往前接**：先拼出核心 `nap`，再在前面加 `s` |
  | 在词尾 | `rest` `sand`（第二周） | **先拼前三再补尾**：先拼 `res` 读出来，再在后面补一个 `/t/` |

  > 第一周只有词首辅音群，所以当时只写了"从后往前接"；第二周出现词尾辅音群立刻打脸。
  > **凡是规范里写"必须/一律"的句子，都要回头问一次：我只有一个样本，凭什么泛化。**
- **认读词每周 ≤ 3 个**，用"就像『的』字，你不用拆开也认识它"这个类比引入。
- **周检 5 个词，全部 CVC，全部是本周从未出现过的保留词**。不要放连辅音或四音词——那测的是新难点，不是迁移。
- **假词要标明是假词**（"只练解码，不是真词"），不能混在真词里。
- **小书开读前必须有大写字母提示**："大写是同一块积木穿了大外套，读音完全一样"。
- 每天打卡 3 条左右；`dayDone` = 该天全部 `checks` 项勾满（跨所有步骤累计）。

## 8. 游戏规范

| 代号 | 名称 | 接管的块 | 规则 |
|---|---|---|---|
| G1 | 声音抓抓乐 | `g1` | 听词拍气球。每轮 8 题（4 正 4 负），答题窗 4000ms |
| G2 | 积木合体 | `blend` | 每词一屏：积木态（点字母听音素）→ 逐音 → 合体。长按确认"他自己读出来的" |
| G3 | 两扇门 | `pair` | 10 题，听音选词，答对开门显示插画 |
| G4 | 点单游戏 | `g4` | 选订单或随机 → 听音 → 从积木架摆词。同词错两次提示首字母 |
| G5 | 造词工坊 | `g5` | 自由摆词，摆满即判。真词与瞎拼**屏幕提示一模一样**，不直接告知对错，让孩子自己读、自己判断。需先完成周检才解锁 |
| G6 | 计时闪卡纪录 | `flash` + `timed` | 记录最好成绩，`isBetter` 统一比较 |

**积木架怎么定（G4 / G5 各一份，两处独立）**

- 架子上放哪些字母，由该游戏的题库反推：G4 只需覆盖订单词，G5 要覆盖整张白名单。
- **每字母放几块，取决于题库里有没有叠字母词**。第一周白名单含 `pip`（两个 p），所以每字母 2 块；第二周订单词和白名单都刻意排除了叠字母词（`dad` / `did` 因此不进白名单），每字母 1 块就够——架子从 12 块降到 10 / 13 块，孩子找字母明显更快。
- 两周累积后架子会越来越长。到字母多得找不过来时，要么按题库收窄 G4 的架子，要么给积木分组，**不要放任它无限变长**。

通用要求：

- 每个游戏都有明确的**回合上限**和**结算界面**，结算写进 `state.games`。
- 长按确认走统一原语 `bindLongPress`，切题 / 复位前必须真取消，不能只清 UI。
- 失败口径统一：答错不判否定，元素晃一下就过，游戏自己记分，家长不评判。
- 游戏状态有**读取清洗层**：schema 不符、保留词混入、数值越界一律丢弃重建，不信任 localStorage 里的旧数据。

## 11. 资产管线

```
tools/audio_manifest_w{N}.json     本周词表 + 每周冻结常量
  → tools/gen_audio.py             edge-tts 批量生成，断点续跑（已有非空文件跳过）
  → assets/audio_raw/              原始 clip（只读，跨周共用，同词不重生成）
  → tools/build_audio.py           裁头尾静音 + 峰值归一（ffmpeg 两遍：测量 → 处理）
  → assets/audio_processed/        可重建缓存
  → 注入 week{NN}.html 的 WORD_AUDIO 锚（原子写出，自检不过就不写）
```

命令（第二周起两个脚本都已参数化，加一周只加一份 manifest，不改脚本）：

```bash
python tools/gen_audio.py   --manifest tools/audio_manifest_w2.json
python tools/build_audio.py --manifest tools/audio_manifest_w2.json --target week02.html
```

**manifest 里必须写的每周冻结常量**（写不全，自检会以为是正则失效而报错）：

| 字段 | 作用 |
|---|---|
| `expected_items` | 条目数，自检① 用 |
| `reserved_blacklist` | 本周周检保留词，自检②④ 用 |
| `source_specs` | 十个提取源各自的 `anchors` / `keys` / `unique` 冻结计数 |
| `g1_round_keys` | G1 轮次键（第一周 `["s","a"]`，第二周 `["c","e"]`） |
| `g5_whitelist_group` | 哪个 group 与 `G5_WHITELIST` 逐词相等（交叉核对用） |
| `unreferenced_keys` | 生成了音频但运行时引用不到的孤儿键，只许改小不许改大 |

- **词表来源不要手写，从页面反推**：用 `build_audio.build_extraction_report(html)` 跑一遍目标 HTML，十个提取源的并集就是本周全部可播放键。这样自检③（引用覆盖）按构造必过，也不会漏词。
- `build_audio.py` 有七项自检，任一失败即非零退出且不碰 HTML。
- **某周不用某个块类型是合法的**（第二周没有 `sentences` 步骤、`WALL_HINT` 为空）：把该源的 `keys` 冻结成 `0`，空源检查会跳过它。冻结成 0 是一次显式声明，以后改回有内容时计数对不上照样会炸，tripwire 语义不减弱。
- **同一个词跨周只录一次**。第二周 73 条里有 37 条直接复用第一周的 raw 文件，只新生成了 36 条。
- 音素真人音来自 Freesound 的 CC BY-NC 音包（教学式孤立发音，需降噪裁剪）。**授权署名必须出现在页脚**。源文件不在仓库里，换周需要重新获取。

### 11.1 插画管线

插画由外部图像模型生成，不在本仓库内跑：

```
图像模型生成 (1024×1024 透明底 PNG，文件名 = art 键)
  → assets/week{NN}/{phoneme|word-cards|book}/ + assets/week{NN}/celebrate.png
  → python tools/embed_assets.py --target week{NN}.html --assets assets/week{NN}
     规格化（192px / 描边 #232B28 3px / 留白 8px / 去外光）+ 注入四个常量，幂等、原子写出
  → 跑一遍 check_data.js + smoke（缺图断言是**配对式**的：图在必须渲染，图不在必须收起容器）
```

- `tools/unify_card_outlines.py` 是库不是 CLI，被 `embed_assets.py` 调用，一般不单独跑。
- **图可以分批补**：工具每次从素材目录全量重建常量，补几张跑一次都行。
- `--dry-run` 先看覆盖情况与孤儿图（文件在、但数据层没引用这个 art 键）。
- 音素助记图只统计"本周真的会渲染 `sound` 块"的那些音——`SOUNDS` 跨周累计，旧音的助记图不会被催。

- **每周单独写一份提示词文件**：`docs/插画生成提示词_第{N}周_{YYYYMMDD}_v{X.Y}.md`。第二周的实例见 `docs/插画生成提示词_第二周_20260831_v1.0.md`，直接照它的结构改内容即可。
- 提示词文件必须包含：通用风格前缀（跨周一字不改）、角色定妆图、逐图主体描述、常见翻车对策、交付检查清单。
- **风格前缀是跨周一致性的唯一来源**，任何一周都不要"优化"它。画风真相源永远是第一周那 34 张定稿插画。
- 抽象词（人称代词、助动词等）画出来会误导，**直接不出图**，页面自动降级成"单词 + 中文"。
- 同一个角色在词卡墙和小书里必须同源——先出角色定妆图，再作为参考图生成场景页。

**回归断言的判据**

修完一个 bug，问一句：**如果它原样再犯一次，我的断言会不会红？** 会红才算修完。
第二周踩过——首页点亮墙的哑巴按钮当初就是被"只数 `data-sayph` 个数"这条断言放过去的；
修好之后如果断言不跟着改成"断言元素类型是 div"，下次同样的错还会再漏一次。
