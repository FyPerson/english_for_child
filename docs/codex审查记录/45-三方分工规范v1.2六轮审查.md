## 实测方法本身的教训

六审的 critical 暴露了一个更深的问题：**五稿我"实测过"的是自己写的等价 Python 代码，不是文档里那段 heredoc 的实际文本**。等价代码没有重复的 `PY`，文档里有。

改法：用 `awk` 从文档提取真实文本再跑。六稿的护栏脚本按此验了三例——正例 `OK/OK` 退出 0、预算调 1 MB 报 `OVER/OVER` 退出 1、`week99` 报 `MISSING` 退出 1。

同一天还有三次「失败的检查看起来像通过」：

- 测 `check_doc_claims` 反例时用 `/tmp`，而 MSYS 的 `/tmp` 与 Windows Python 的 `/tmp` 不是同一目录 → 反例没报，差点判定脚本失效（今天踩了两次）
- 在 GBK 乱码输出里 `grep -c "行"` 统计条数 → 恒为 0
- 扫非 ASCII 时 `grep -P` 在 `LC_ALL=C` 下全部报错，脚本却打印了「以上为空 = 都是 ASCII」

**唯一有效的防御是每个检查都跑一个已知会失败的样本。**

## 一条实测澄清

原文写「脚本输出一律用 ASCII，非 ASCII 会抛 `UnicodeEncodeError`」——不准确。实测：

- `print('中文测试')` **不崩**，只是显示乱码（中文在 GBK 字符集里）
- `print('✗')` **崩**，`✗` 不在 GBK 里

已改为分情况的表格：判定字样用 `OK`/`FAIL`/`OVER`/`MISSING`，说明性中文无妨。

## 已知缺口（六审建议，记录待办）

1. **`META.status` 的 scaffold/final 门禁没有工具支持**。起点周必须登记进 `weeks` 才能构建，登记后 `build/weekNN.html` 就实实在在生成。三道人工闸门里只有「标题加 `[未定稿] ` 前缀」在文件被拷走后仍有效。要补：`release`/`package` 遇到 scaffold 直接拒绝、`courseWeeks` 含 scaffold 即构建失败。
2. **`doctor` 没有只验基础环境的参数**。它会实际启动 Chromium，起不来就 `SystemExit`，所以无法既要求它 PASS 又说「Chromium 装不上不阻断阶段 B」。现行口径是两种可接受结果，等工具补参数后收敛成一种。
3. **键级校验与体量护栏仍是「照着文档跑脚本」**，没有封装成仓库里的工具。副机每次要自己拼命令。等第 1 期媒体清单化时一并做成 `tools/` 下的正式脚本。
