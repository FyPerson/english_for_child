## 通道账本（本段最重要的运维发现）

**用户 2026-09-09 改规则**：09-08 归档 46 记的是「后续默认走订阅，不再先试 API」；本段开工前用户改为——**每一轮送审都先从 API 中转起算、重试 3 次，3 次全败才该轮换订阅；下一轮仍从 API 重新开始**。回退是**单轮级**，不是段级。

本段实证：

| 轮次 | 通道 | 材料量 | 结果 |
|---|---|---|---|
| S0 首审 第 1 次 | API 中转 | 80 KB | 失败 `stream disconnected` |
| S0 首审 重试 1 | API 中转 | 80 KB | **成功** |
| S1+S2 合并审 第 1 次 | API 中转 | 80 KB | 失败 `stream disconnected` |
| S1+S2 合并审 重试 1 | API 中转 | 80 KB | 失败 `stream disconnected` |
| S1+S2 合并审 重试 2（缩小材料） | API 中转 | 53 KB | 失败 `OpenAI Responses protocol violation at stream_end` |
| S2 核心审（回退） | 订阅 `gpt-5.6-sol` | 53 KB | **成功** |

**结论**：失败与材料量无关——缩小 34% 后仍败，且第 3 次给出的是**协议层**错误（`stream ended without a terminal response event`）。是 API 中转侧的问题。中途我曾据前两次数据推测「80 KB 是不稳定区」，**该假设已被第 3 次证伪**，锚点里保留了纠错痕迹。

**成功判据三条缺一不可**：`final.txt` 存在且非空 + `skipped-context-budget` 0 命中 + `contextFilesCount` 等于传入数。⚠️ **`exitCode 0` 与 `timedOut false` 具有欺骗性**——四次失败全部是 exit 0。

## 执行中超出方案预期的三处发现

1. **旧 `usedWords` 漏的是五处不是两处**（第 3 步）。方案只说漏 `wordforge`、`BOOK.pages`；逐一走查规范块类型表与 12 常量表后确认还漏了 `G3_PAIRS`、`G5_WHITELIST`、`WALL_HINT`。`G4_WORDS` 收了而 `G5_WHITELIST` 没收是不对称遗漏；`G3_PAIRS` 现恰好与 DAYS `pair` 块逐字相同才侥幸被间接覆盖，但无 schema 保证两者一致
2. **组合多解**（第 2 步）：本周新教的多字母字位，若其组成字母都已单独教过，该周**所有**含该字形的词必然多解。W5 教 `ai` 而 W1—W4 已教 `a`/`i`，实测 `rain`/`tail`/`mail`/`sail`/`pain`/`main`/`aim`/`air`/`hair`/`chair`/`snail`/`paint` 全需 `segments` 消歧。与同形多音无关，是另一类。待追认 P3
3. **方案步间依赖表缺 `3←4a`**（第 3 步）：真实数据仍是 `L` 字段而 `segmentWord` 要 `grapheme`。按「S3 自带临时只读适配层」处置，待追认 P6
