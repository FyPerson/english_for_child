## 第二层：4 件套

### H-1（high）候选残留可能进入提升流程
> codex 原话：脚本只检查 `<out>/*.wav`，不检查 `<out>/candidates/*.wav`；README 的 b 提升命令又未带 `--clean`。如果 `tmp/b_only/candidates` 留有另一个、且同样被 week03 声明的旧候选，后续 `build_phonemes.py --src tmp/b_only/candidates` 会把它与 b 一并注入，绕过"候选逐个听检后提升"的隔离意图。
> codex 建议：`--include-candidates` 时也对 `candidates/*.wav` 按 `produced` 集合做残留检测；README 提升命令带 `--clean`，确保 `--key b` 最终只留下 b。

**建议：采纳。** 候选机制是为 C-1 新建的隔离，隔离有缝就等于没建。两处改动各一行。
**不采纳理由**：`tmp/b_only` 是临时目录，正常用法不会积累旧候选；`--clean` 已能删候选子目录，只是文档没写。
**🔟 第十人（历史踩坑）**：「清单复用键整条继承」和首轮 M-4 都是"残留混入"一类，这是同一坑第三次以不同形态出现——说明我写护栏时只想着主路径，没把候选路径当成同等的注入入口。采纳，并把"任何会被 build_phonemes 当源目录的地方都要做残留检测"记进脚本注释。

### M-1（medium）哈希与字节数未必填
> codex 原话：`validate()` 的必填列表遗漏 `sha256` / `bytes`，`fetch()` 接受 None，未来新增来源漏填会静默退化为不校验，与脚本说明矛盾。
> codex 建议：纳入必填；sha256 须 64 位十六进制，bytes 须正整数且拒绝布尔；`fetch()` 参数改非可选。

**建议：采纳。** 首轮 H-3 的价值就在"漏填也会被拦"，可选参数把它变回了许愿。
**不采纳理由**：可选设计对"先试听再补哈希"的探索阶段友好。但探索可以在拿到哈希之前不写进 spec。
**🔟 第十人（成本 / 价值）**：多 6 行校验，代价可忽略；用 3 个角度检查后未发现实质反驳，确认采纳。

### M-2（medium）下载异常不清理 `.part`
> codex 原话：`urlopen`、`r.read()`、写盘或网络中断抛异常时没有清理逻辑，可能留下部分文件；原缓存不会被覆盖是安全的，但"所有失败路径干净"尚未成立。
> codex 建议：`try/finally` 包住下载与校验，仅原子替换成功后保留；下载前先删同名旧 `.part`。

**建议：采纳。** 我在复审 brief 里写了"失败路径干净"，实际只覆盖了校验失败一条路径，这是"能力声明 ≠ 实作"。
**不采纳理由**：残留 `.part` 不会被当成缓存（校验看的是 `.mp3`），只是脏文件。
**🔟 第十人（基础假设）**：无实质反驳；改动 5 行。确认采纳。

### M-3（medium）护栏判定在写盘之后
> codex 原话：guard 失败时删除刚写的文件，也同时丢失该路径原先可能存在的合格输出；未用 `--clean` 的失败重跑不是保留旧成果的原子操作。
> codex 建议：写盘前完成 guard 判定；或先写临时文件、全部通过后 `os.replace()`。

**建议：采纳（两者都做）。** guard 的计算只依赖 x / y 和切点，天然可以放在写盘前；临时文件 + `os.replace` 与 build_phonemes.py 的原子写出习惯一致。
**不采纳理由**：配合 `--clean` 使用时没有"旧成果"可丢。但护栏不该依赖调用方记得加参数。
**🔟 第十人（心智成本）**：无实质反驳；确认采纳。

### M-4（medium）类型校验不严、`inject` 接受模糊值
> codex 原话：`bool(it.get("inject", True))` 把字符串 `"false"` 当 true，本应进候选的资源会写到顶层；guard / source 未验证为对象，band 元素未验证有限数值，配置错误时抛 TypeError 而非带键名的可诊断错误。
> codex 建议：`inject` 必须是 JSON 布尔；条目、source、guard 为对象；band 两端为有限非布尔数值；候选控制采用失败关闭。

**建议：采纳。** `inject` 是 C-1 的开关，开关本身接受模糊值是最不该有的缝。
**不采纳理由**：spec 由我写、JSON 里 `false` 就是布尔，"false" 字符串是想象中的错误。但 spec 明确要给 GPT 副机和换机后的人复跑，防呆值得。
**🔟 第十人（时间）**：无实质反驳；确认采纳。

### L-1（low）底噪区间约束与 STFT 半窗重叠
> codex 原话：`nr_db=0` 时仍强制 `noise_sample_end ≤ start`，会误拒绝开头立即发音但不需降噪的来源；启用降噪时底噪末帧的窗可覆盖音素起始约半个 FFT 窗。当前切点间隔充足，不受影响。
> codex 建议：仅 `nr_db>0` 时校验；要求间隔 ≥ `N_FFT/(2·sr)`，或改显式区间。

**建议：采纳（前两项，不做显式区间）。** 两处都是条件判断，不改数据格式。
**不采纳理由**：本周不受影响，可以推到真遇到时再改。
**🔟 第十人（时间）**：现在改 3 行，将来遇到时要先排查再改；确认采纳。
