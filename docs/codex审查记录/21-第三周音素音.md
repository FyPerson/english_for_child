## 第二层：4 件套

### C-1（critical）/b/ 的元音起始
> codex 原话：/b/ 明确从 "ba" 中保留了约 80ms 元音起始，即使淡出到 -25dB，仍可能被儿童听成 buh/ba。这直接触及"孤立辅音不能带 schwa 尾音"的硬约束，也会污染 b/d、p/b 的音素对比教学。
> codex 建议：在获得真正孤立的真人 /b/ 前，不要给 b 渲染听音按钮；从 PHONEME_AUDIO 移除 b，让页面按铁律 8 显示家长口令。若保留该资源，至少应先定义并执行可重复的元音尾检测门槛。

**建议：采纳（降级 + 留候选）。** 红线是项目自己定的，不能用"可能没那么糟"绕过；教错的代价（孩子拼 bag 念 buh-æ-g）远大于降级的代价（家长自己示范 b，页面已支持这种形态）。README 明文警告"从单词里切一刀"这条路，b 正是这么来的。
**不采纳理由**：b 的元音起始（约 60 ms）比已在用的 d（约 100 ms）还短，按同一尺子 d 也该下架；用户本来就要逐段听检，先放着听完再定不亏；b 是本周词卡出现最多的辅音之一（bag bed big bug bus tub…），整周没有听音按钮是实打实的教学损失。
**🔟 第十人（基础假设）**：我原先"给音频 + 标注最需把关"的决定带着完成偏差——想把六个凑齐。反过来质疑 codex：它没听过这段音，"critical"依据是我文字里的"80 ms"和规则文本，不是听感。但规则本身就是为了防"听起来差不多"的自我说服而定的红线，红线面前听感不是抗辩理由。时间维度：降级只到用户听检或自录为止，多等一天。**走完确认采纳。**

### H-1（high）g 的浊化段
> codex 原话：g 的 0.68–0.80 秒浊化嗡音被完全排除，只保留爆破与释放。这样可能听起来接近无声的 /k/，削弱规范中要求孩子通过喉咙振动区分 k/g 的教学目标。第二周 d 的切法不能自动证明 g 也应去掉浊化段。
> codex 建议：重新评估并保留足够的闭塞期浊化片段，或在规格中明确 g 的目标实现是"有声闭塞+爆破"还是仅爆破；验收应针对 k/g 的可感知差异。

**建议：不采纳（保持切点），spec 加回退说明。** 核实结果：g 的释放段从爆破后 10 ms 起就是浊化的（低频谐波），c 的 /k/ 释放是无谐波的送气噪声，两者对比明显；d 与 g 同型。加 120 ms 嗡音会让 g 听起来像 "ng-g"，且与前两周所有塞音形态不一致。切点是 spec 里的一个数字，听检不满意改 start 为 0.68 即可。
**不采纳的反向理由（即采纳理由）**：口令写的是"靠喉咙振动分"，带嗡音的 /g/ 孩子摸喉咙能直接感到；"与 d 一致"只是形式一致，d 自己还没听检过。
**🔟 第十人（历史踩坑 / 时间）**：以 d 为基线的基线本身未验证——如果听检发现 d 也该带嗡音，那是两周塞音统一改，不是现在单改 g。**走完确认不采纳。**

### H-3（high）缓存无哈希
> codex 原话：缓存只按 sound_id 和键命名，以"文件存在且大小大于 0"判定可复用；没有 SHA-256、Content-Length 或下载完整性校验。

### M-1（medium）解码器不一致
> codex 原话：prep 用 soundfile/libsndfile 解码 MP3，build 用 ffmpeg；不同解码器可能产生采样、时长和峰值差异，削弱"可复现"声明。
> codex 建议：统一由同一套 ffmpeg 解码，或锁定并记录版本。

**建议：部分采纳。** prep 改用同一个 imageio_ffmpeg 解码试听流为 PCM，并打印输出 WAV 的 sha256；不做版本清单。
**不采纳理由**：两个解码器对 mp3 的差异在采样级，对 10 ms 粒度切点和 -3 dB 归一没有实质影响。
**🔟 第十人（基础假设）**：真正的收益不是"精确复现"，而是去掉 soundfile 解 mp3 这个隐性依赖（libsndfile ≥ 1.1），换机少一个坑——这才是采纳的理由。

> codex 建议：对 /f/ 增加频带能量保留或谱质心下限等自动护栏；不满足应让该键失败而不是静默产出。

**不采纳理由**：护栏是给未来周次的，本周数据已证明 f 无事，可只记录不设门槛。
