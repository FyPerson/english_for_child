## 第一层：非技术总结

方向没问题，但 v0.1 是"决定清单"，不是"可执行清单"。codex 抓的两条 critical 都是"做了却验不了、或做错了回不去"：一是第 1 期靠一份只含哈希的 manifest 当基线，导出媒体前没有准入校验，字节不变无法证明；二是历史重写这种不可逆操作缺少硬门槛。七条 high 集中在一件事：方案写了"改工具、改测试、改文档"，却没有列出到底改哪些文件、契约长什么样。核实时还发现三处本地事实让问题更实：内嵌媒体里有 12 个 webp，导出一律存 png 会改字节；每周 HTML 含两处 `</script`，不转义直接放进 JSON 脚本块必截断；三个素材工具各有一套注入文本格式，"整文件哈希不变"根本做不到，必须改成"骨架 + 每键媒体摘要"两层定义。

## 第二层：4 件套

### C-1（critical / missing-constraint）§4 第 0 期第 1 步、第 1 期第 1 与第 4 步
> codex 原话：基线只复制 Release 的 manifest.json，里面只有哈希，不能作为"读取基线构建产物并逐键导出媒体"的输入。第 0 期第 5 步还会故意改变 course.html，当前方案没有定义基线中 course 哈希的弃用范围。
> codex 建议：明确基线结构，导出工具先对输入做哈希校验，记录第 5 步后的 course 新哈希，不要只依赖本机 dist。

**建议：采纳。** 核实时发现比 codex 说的更根本：三个素材工具各有一套注入格式，第 1 期换成统一生成器后整文件哈希必变，所以"字节不变"要定义成"骨架 sha256 + 每键 [键, mime, 解码字节 sha256] 列表"两层，整文件哈希只用于导出前准入。
**不采纳理由**：可以不入库基线、只在本机 dist 里比对。但 dist 不随 clone 走，历史重写后旧 HTML 也不在 git 里，基线不入库就没有第二份证据。
**🔟 第十人（基础假设）**：我在 v0.1 默认"构建可重现所以基线随时能重算"，但基线要证明的恰恰是迁移前后的等价，迁移后就没有"前"了。采纳。

### C-2（critical / security）§4 第 0 期第 7 步
> codex 原话：不可逆操作但前置条件不完整：没有要求工作区干净、fetch 并核对远端引用、检查 tags/stash/未推送，也没说明重写后如何处理引用；预期体量还受 reflog 影响。
> codex 建议：加硬门槛、bundle 可恢复性验证、明确引用范围、gc 后记录实测体量。

**建议：采纳。** 实测当前 tag 0、stash 0、未推送 0，但本地有 backup/pre-reword 领先 main 3 个提交，这正是门槛要拦的东西。
**不采纳理由**：单人项目、副机只推 main，门槛看起来多余。但 G 是用户逆建议做的决定，越是这样越要把不可逆的那一步写死。
**🔟 第十人（历史踩坑）**：项目记忆《修复也是改动》说删旧防护前先盘点防护范围；这里是"删旧历史前先盘点引用范围"，同一类。采纳。

### H-3（high / ambiguity）§3 清单示例、§4 第 1 期第 2 步
> codex 原话：文字称"键→文件路径 + mime"，示例只有字符串；七个声明的顶层结构、空声明、别名、键顺序、重复路径和 MIME 格式未定义。
> codex 建议：给出完整 schema 与校验规则。

**建议：采纳。** §3.2 六条规则里第 5 条（键序按 JSON 顺序、不排序）和第 6 条（固定生成格式）是为 C-1 的两层验收服务的，缺一不可。
**不采纳理由**：schema 可以等第 1 期实现时再定。但方案就是给实现定契约的，留白等于让实现者猜。
**🔟 第十人（心智成本）**：六条规则是不是过度设计？逐条看：每条对应一种会改字节或会让构建不确定的情况，去掉任何一条验收就不可证伪。采纳。

### H-4（high / contradiction）§4 第 0 期第 2 步、§5
> codex 原话：`build_lessons.py --check` 依赖根目录已有 HTML；不入库后 fresh clone 没有可比较文件；先 build 再 --check 变成自检。
> codex 建议：明确唯一契约并同步 project.py、run_checks.py、README、CI。

**建议：采纳。** 把 `--check` 改用于"可重现构建"是它在新模型下唯一有意义的用法：两次构建哈希不同就是构建不确定，这是清单化后新增的风险。
**不采纳理由**：可以直接删掉 --check。但可重现性检查几乎零成本，且 Release 用同一批字节这条验收要靠它。
**🔟 第十人（时间维度）**：现在只有四周，构建确定性看似不成问题；到 40 周、多人改清单时才会出现。采纳。
