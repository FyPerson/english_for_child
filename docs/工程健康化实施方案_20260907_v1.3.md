# 工程健康化实施方案 v1.3

## 0. 这份文档管什么

2026-09-06 的目录重构把源码、素材、测试、工具分开了，工程骨架合格。本方案解决剩下的两个问题：

- **交付格式被当成了源码格式**：同一段媒体的字节在仓库里存三到四份、生成物随每次改动进 git、媒体声明从产物反向回写。
- **交付格式本身不随周数扩展**：周文件把复习要用的旧媒体整份再内嵌一遍，合并入口再把全部周文件整份内嵌一遍。按第一年 40 周、预留到 50 周推算，合并入口会到 100 MB 以上，任何阈值都拦不住。

目标是从现在起止住线性膨胀，并让受护栏约束的对象都是**单文件或单周新增**指标：周文件、壳、单个媒体文件、本周新增媒体，没有任何一条护栏量的是"到本周为止的总量"。壳的清单随周数线性增长，50 周约 15 KB，受 `shell` 上限约束；`media/` 总字节只是观察性报告。护栏不能保证某一周素材放大了也不触线，那正是它要抓的：触线是需要处理的信号，处理方式是查该周清单，放宽必须拍板。

不在本方案范围：教学内容、第四周试课、第四周设计落差（另案）、后端（六年内不需要）。

### 3.2 媒体清单 schema

```json
{
  "schemaVersion": 1,
  "week": 4,
  "declarations": {
    "PHONEME_AUDIO": {"s": {"path": "resources/assets/phonemes/s.mp3", "mime": "audio/mpeg"}},
    "WORD_AUDIO":    {"sat": {"path": "resources/assets/audio_processed/sat.mp3", "mime": "audio/mpeg"}},
    "PHONEME_ILL":   {"snake": {"path": "resources/adopted/phoneme-ill/snake-3fa9c2b1e0.png", "mime": "image/png"}},
    "WORD_ILL":      {},
    "WALL_ILL":      {},
    "BOOK_IMG":      {},
    "CELEBRATE_NAT": {"path": "resources/adopted/celebrate/week04-8c1d0e77aa.png", "mime": "image/png"}
  }
}
```

规则，任一违反构建失败：

1. 顶层只允许 `schemaVersion`、`week`、`declarations` 三个键；`declarations` 必须恰好含七个声明名，不多不少；声明内条目只允许 `path`、`mime` 两个字段。
2. 六个对象声明的值是键值映射，允许空对象；`CELEBRATE_NAT` 的值是单个 `{path, mime}`，不允许空。
3. 键必须匹配 `^[A-Za-z0-9 ,.!?-]{1,80}$`（四周 652 个现有键全部满足）；JSON 用拒绝重复键的方式解析（Python `object_pairs_hook`），同一声明内重复键即失败。
4. `path` 是仓库相对的 POSIX 路径：只允许 `/` 分隔，出现反斜杠即失败；禁止 `..` 与绝对路径；`realpath` 解析后必须位于真实的 `resources/` 树内（符号链接逃逸即失败）；目标必须是普通文件，目录或不存在即失败。
5. `mime` 只允许 `audio/mpeg`、`image/png`、`image/webp`；扩展名必须与 mime 一致（`.mp3` / `.png` / `.webp`）。
6. 同一文件可被多个键、多个声明、多个周引用（别名与跨周共享）。
7. 键顺序以 JSON 文件中的顺序为准，生成声明按此顺序输出；构建不排序。
8. 生成文本固定：对象声明为 `const NAME = {` 一行、每键一行 `  '<键>': '<值>',`、末行 `};`；空对象为单行 `const NAME = {};`；字符串声明为单行 `const CELEBRATE_NAT = '<值>';`。`<值>` 在引用形态为 `media/<sha256 前 16 位>.<ext>`，在单文件形态为 `data:<mime>;base64,<b64>`。一律 LF、无注释、无其他常量。这三种写法都能被 `tools/validation/load_data.js` 的 `declaration()` 解析（多行以 `^\s*[}\]];` 结束、单行以首个 `;` 结束），单元测试用 `declaration()` 解析七类声明各一次，并含一个"缺少结尾 `};`"的截断反例。

模板侧把七个 `<!-- @include media/weekNN/<name>.js -->` 改为同位置的 `<!-- @media weekNN NAME -->`，位置不动。构建规则：`@include media/` 与 `@media` 在第 1 期并存期可以同时被识别，但**同一个声明名在一个模板里只能出现一次**；构建先枚举模板里全部 `@media` 与 `@include media/` 标记，按声明名计数，出现两次、出现未知指令或未知声明名即失败。反例测试：缺声明、多余顶层键、重复键、非法键字符、反斜杠路径、目录路径、符号链接逃逸、`..` 路径、未知 mime、扩展名不符、文件缺失、同名声明出现两次、截断声明。

### 3.3 基线与"字节不变"的定义

基线文件 `tests/fixtures/baseline_20260907.json`（入库），四周齐全：

```json
{
  "schemaVersion": 1,
  "takenAt": "2026-09-07",
  "sourceCommit": "<40 位十六进制 SHA-1>",
  "form": "single-file",
  "toolVersions": {"python": "3.12.x", "node": "v22.x.y", "hash": "sha256"},
  "weeks": {
    "week01.html": {
      "sha256": "...",
      "skeletonSha256": "...",
      "declarationOrder": ["PHONEME_ILL", "BOOK_IMG", "WALL_ILL", "WORD_ILL", "CELEBRATE_NAT", "WORD_AUDIO", "PHONEME_AUDIO"],
      "media": {"PHONEME_AUDIO": [["s", "audio/mpeg", "<sha256>"]], "CELEBRATE_NAT": [["", "image/png", "<sha256>"]]}
    },
    "week02.html": {}, "week03.html": {}, "week04.html": {}
  },
  "course": {"sha256": "<整文件哈希，只作记录，不参与比对>"}
}
```

- **生成入口**：新增一次性命令 `python tools/project.py baseline --create`。前置：工作区与 index 干净；目标 fixture 不存在，已存在则拒绝，除非显式 `--force`。命令内部固定执行 `build --single-file --output-dir <临时目录>` 并记录 HEAD，与默认形态无关；`check` 里的基线比对同样只读单文件形态产物，第 1b 期起由 `check` 自己额外跑一次 `build --single-file --output-dir <临时目录>` 取得它。**普通 `build` 与 `check` 只读取和比较基线，绝不写它**。错误形态拒绝测试两例：给比对函数一份引用形态周文件与 `form` 为 `single-file` 的基线，必须失败；给一份单文件形态周文件与 `form` 为 `reference` 的基线，必须失败。行为测试：预置基线并记录字节与 mtime，分别运行 `build` 与 `check` 后断言二者不变；`baseline --create` 在文件已存在且无 `--force` 时被拒绝。
- `form`：恒为 `single-file`。第 0 期现行产物就是这种形态；第 1b 期默认形态切换后，基线命令与比对仍走 `--single-file`，不随默认形态变。
- `sha256`：整文件哈希，用于第 1 期导出前的准入校验。
- `skeletonSha256`：先用正则枚举全文所有 `^const <NAME> = ` 起点，七个声明名各必须恰好一次，否则失败；再用 `load_data.declaration()` 确定每段结束边界；每段替换为固定占位符 `/*@MEDIA <NAME>@*/` 后取哈希。
- `declarationOrder`：七个声明在文档中的出现顺序。
- `media`：每声明按键序的 `[键, mime, 解码字节 sha256]` 列表；字符串声明的键记为空串。引用形态下，"解码字节"指声明值所指 `media/` 文件的字节。
- 可证伪测试四类：重复声明必须失败；声明换序必须改变 `declarationOrder`；缺结尾必须失败；声明之外的普通文本改一个字符必须改变 `skeletonSha256`。
- course.html 只记录整文件哈希，**不参与任何比对**。

第 1 期"字节不变" = 四个周文件的 `skeletonSha256`、`declarationOrder`、`media`（键数、键序、mime、字节）与基线完全相等。它比整文件哈希弱的只有一处：声明文本的写法，已由 §3.2 第 8 条固定。第 1b 期把桥接放进每个周文件后 `skeletonSha256` 必然变化，所以第 1b 期第 2 步起比的是**去桥接骨架哈希**。桥接在模板里是一个**注入块**：从 `<!-- @course-bridge start -->` 到 `<!-- @course-bridge end -->`（含两行标记，独占整行）之间是一个完整的 `<script>` 元素，里面只有 `@include shared/course-gate.js` 与 `@include shared/course-bridge.js` 两个 include；块外不允许出现这两个 include。算法：先整块删除注入块（含标记行、`<script>` 标签与这些行的换行，删到与不含桥接的模板逐字节相同），再按 `skeletonSha256` 的算法取哈希，必须等于基线 `skeletonSha256`；起止标记各必须恰好出现一次，否则失败；第 1b 期第 1 步模板尚无注入块，此时算的就是普通 `skeletonSha256`。`declarationOrder` 与 `media` 照比。三项全等后才允许在期末用 `baseline --create --force` 重取基线作为后续周的准入基线；`check` 打印这份比对结论。可证伪测试两例：在注入块外多放一个 include 必须失败；改动注入块内一个字符后去桥接哈希不变而普通哈希改变。

### 3.4 构建与检查契约

- `build_lessons.py`：产物写 `build/`（第 0 期第 2 步起），`--output-dir <目录>` 覆盖；原 `--check` 删除。第 1b 期起默认输出引用形态：周文件的声明值为 `media/<sha256 前 16 位>.<ext>`，构建把清单引用的源文件按此名**逐字节复制**到 `build/media/`，同内容只复制一次，复制后核对 sha256；`--single-file` 输出 data URI 形态的周文件，不产壳，不产 `media/`。
- **原子替换与残留**：构建先写到与 `build/` 同文件系统的临时目录，全部产物写完并自检后原子替换 `build/`（旧目录先改名再删除，失败时改回），`build/` 里不会有上一次构建的残留；单元测试预置一个陈旧文件后 build，断言它不在 `build/` 里。
- **单文件形态的约束**：`--single-file` 必须显式给 `--output-dir`，且不得是 `build/` 或其子目录，否则失败；它输出每个文件的字节数，任一文件超过 8 MB 时非零退出，除非显式 `--allow-large`；`release`、`serve` 与 CI 都不使用它，单文件不进 Release。
- `check` 按编号顺序执行，前一步失败即停：① 默认形态 `build`（写 `build/`）；② 默认形态 `build --output-dir <临时目录 A>`，与 `build/` 逐文件比较全部产物（含 `media/` 下每个文件）的 sha256，不同即失败（可重现构建）；③ 基线比对：第 1b 期起 `build --single-file --output-dir <临时目录 B>`，只取其中四个周文件按 §3.3 比三项（`course.html` 不比）；第 0 期与第 1 期默认形态就是单文件形态，③ 直接读临时目录 A 的四个周文件，不再构建；④ 其余作业：目录布局、构建边界、测评契约、媒体、体量护栏、浏览器回归。临时目录 A、B 在 `check` 结束时无论成败都删除。fresh clone 上 ① 先写出产物，后续作业读它们。
- `release` = `check` 通过后直接 `package` `build/` 整目录到 `dist/<版本>/`，**不再构建第三次**；`package` 只接受白名单：`course.html`、`index.html`、`weekNN.html`、`media/` 下按 §3.1 命名的文件，其余文件存在即失败。`manifest.json` 的 `files` 以相对 POSIX 路径为键，覆盖目录内全部文件。`serve` 同理。
- `--quick` 同样执行 ① ②。README、development.md、CI 三处命令说明同步。

### 3.5 体量护栏

**长期指标**（第 1b 期第 4 步起生效），`project.json`：

```json

```

| 指标 | 计算对象 | 为什么不随周数累计 |
|---|---|---|
| `weekHtml` | `build/weekNN.html` 每个文件的磁盘字节 | 引用形态下只含代码、数据、内嵌字体，现状 0.2 MB |

另打印一个**报告项**，不判定：`media/` 总字节。单文件形态的体量规则见 §3.4（超过 8 MB 须 `--allow-large`）。

计算对象是 `build/` 下每个 `weekNN.html` 与 `course.html`；`index.html` 不计。它们是累计量，只为在第 1b 期落地前拦住意外膨胀；四周现状 7.38 与 13.57 均在线内。第 1b 期是硬截止（§7），本方案不写放宽预案。

### 3.6 合并入口：壳与桥（第 1b 期）

**壳** `course.html`：

- payload 只含 `{"weeks":[{"n":1,"key":"soundblocks-w1-v1","checks":[[...],...]}, ...]}`，不含周文件正文；`openWeek(n)` 把 `frame.src` 设为 `weekNN.html`，删除 srcdoc、atob、TextDecoder。
- 门控计算（`completion` / `allowed`）移到 `frontend/src/shared/course-gate.js`，壳与周文件都 include 同一份，输入为周清单与 localStorage。
- 壳与周文件之间只用 `postMessage`，不做任何跨框架直接访问（§2 实测本地文件下会抛 `SecurityError`）。
- **会话号**：壳每次 `openWeek` 生成随机 `sessionId`（16 位十六进制），先作废旧会话（清掉未到期的计时器，此后带旧号的回包一律忽略），再设 `frame.src`；`gate` 消息带 `sessionId`，周文件之后的每条消息都回带同一 `sessionId` 与 `week`；壳只接受当前 `sessionId` 且 `event.source === frame.contentWindow` 的消息，周文件只接受 `event.source === window.parent` 的消息；消息一律带 `type` 前缀 `soundblocks:` 与 `version: 1`，字段缺失或类型不符即忽略。
- **发送目标**：`location.protocol` 为 `file:` 时 `targetOrigin` 用 `'*'`（本地文件下 `event.origin` 恒为字符串 `"null"`，只能靠会话号与 source 校验），否则用 `location.origin`；壳与周文件两侧同规则；iframe 换 src 即作废会话。

**协议**：

| 方向 | 消息 | 触发 | 对方动作 |
|---|---|---|---|
| 壳 → 周 | `soundblocks:gate {sessionId, weeks}` | iframe `load` 后 | 周文件激活桥接，用清单与 localStorage 本地同步计算 `allowed` |
| 周 → 壳 | `soundblocks:ready {sessionId, week, progressDigest}` | 收到 gate 后 | 壳记录就绪；`progressDigest` 由 `course-gate.js` 里同一个函数计算：对 `localStorage.getItem(key)` 返回的原始字符串取 `{exists, length, hash, error}`，`length` 是 JavaScript 字符串长度（UTF-16 码元数），`hash` 是该串的 32 位 FNV-1a，不解析 JSON；读取抛异常或返回非字符串时固定为 `{exists:false, length:0, hash:0, error:true}`；壳对同一键自己算一份，任一字段不一致即显示"当前浏览器不共享本地进度，请用 Chrome 或 Edge 打开，或部署到网站后使用；可先在本周课件里导出备份，再到壳里恢复" |
| 周 → 壳 | `soundblocks:saved {sessionId, week}` | 周文件每次保存后 | 壳 `refresh()` |
| 壳 → 周 | `soundblocks:leave? {sessionId, requestId}` | 用户点另一周前 | 周文件按 `progressDirty` 与 `confirm` 决定，回 `soundblocks:leave {sessionId, requestId, ok}`；壳按下面的离开状态机处理 |
| 壳 → 周 | `soundblocks:refresh {sessionId}` | 壳 `refresh()` 时 | 周文件重算锁定态（原 `courseRefresh`） |

**字段与接收条件**（缺字段、类型不符、值不在允许范围一律忽略并计数，不抛错）：

| 字段 | 类型与允许值 | 出现在 |
|---|---|---|
| `type` | 字符串，恰为五个 `soundblocks:` 前缀值之一 | 全部 |
| `version` | 整数 1 | 全部 |
| `sessionId` | 16 位小写十六进制字符串 | 全部 |
| `week` | 整数，1 到 `courseWeeks` 长度 | `ready`、`saved`、`leave` |
| `requestId` | 正整数，壳侧单调递增 | `leave?`、`leave` |
| `weeks` | 数组，每项 `{n: 整数, key: 非空字符串, checks: 字符串数组的数组}`，`n` 从 1 起连续 | `gate` |
| `progressDigest` | `{exists: 布尔, length: 非负整数, hash: 非负整数, error: 布尔}` | `ready` |
| `ok` | 布尔 | `leave` |

接收条件：壳侧 `event.source === frame.contentWindow`、`sessionId` 等于当前会话、`week === selectedWeek`；周文件侧 `event.source === window.parent`、`sessionId` 等于已收到的 `gate` 会话；非 `file:` 协议下两侧再各加 `event.origin === location.origin`，`file:` 下不校验 origin。

**离开状态机**（壳侧）：`idle` → 点另一周 `target` 时进入 `waiting(target, requestId)` 并发 `leave?`；收到 `ok:true` 且 `requestId` 等于当前 → 切到 `target`，回 `idle`；`ok:false` → 回 `idle`，停在本周；`LEAVE_TIMEOUT_MS` 到期 → `timedOut(target, requestId)`，显示"正在等待课件响应"与"重试"、"留在本周"两个按钮；"重试"取消旧计时器、`requestId` 加一、回到 `waiting`；"留在本周"回 `idle`；在 `waiting` 或 `timedOut` 里点别的周 → 作废当前 `requestId`，对新目标重新进入 `waiting`；任何 `requestId` 不等于当前的 `leave` 回包一律丢弃，界面不变。

**周文件侧**：`course-bridge.js` 从"只注入合并版"改为**每个周文件都包含**，但只在 `window.parent !== window` 且收到合法 `gate` 消息后激活；未激活时不改任何行为，直接打开周文件与今天完全一样。桥接激活后的行为与现在相同：未解锁的天回首页、`[data-goto]` 加锁、点击拦截、保存后通知壳。

**超时常量**：`READY_TIMEOUT_MS = 2000`、`LEAVE_TIMEOUT_MS = 1000` 定义在 `course-gate.js`，不做用户配置；慢端测试用 Playwright 的 CPU 节流（4 倍）与注入延迟回包各跑一遍，数值若被实测推翻就改常量。

**失败与兜底**：壳发出 `gate` 后 `READY_TIMEOUT_MS` 内未收到 `ready`（周文件 404、脚本错误、被浏览器拦截）→ 壳显示"这一周没有加载出来"与该周文件的直接链接，不留空白。壳仍监听 `storage` 事件以响应另开窗口的保存，但不依赖它。

**测试**（`tests/browser/test_course.py`，本地文件与 http 两路都跑）：解锁与重新锁定流程；`leave?` 拦截；`ready` 超时显示错误与链接（用不存在的周文件构造）；直接打开周文件时桥接不激活（`[data-goto]` 无 course 锁）；`progressDigest` 不一致时的提示（用注入脚本模拟）；切换周后注入带旧 `sessionId` 的 `saved` 回包必须被忽略；`leave?` 超时后的"重试"与"留在本周"；迟到的 `leave` 回包不改变界面、重试生成新 `requestId`、等待中切换目标取消旧请求；注入抛错的 localStorage 时两侧 `progressDigest` 相等且 `error:true`；CPU 节流 4 倍下 `ready` 不超时。http 路再加 404、带路径前缀部署两组。真机验收：Windows Chrome 与 Edge 本地目录、iPad Safari 经 http。

### 3.7 CI 与 Release

`.github/workflows/check.yml` 改为两个 job：

| job | 触发与条件 | 步骤 | 权限 |
|---|---|---|---|

### 3.8 adopted 文件命名与生命周期

- **适用范围**：本节只约束 `resources/adopted/`，即 `embed_assets.py` 与导出工具产出的插画、以及前两周 34 条一次性导出的词音。音素与词音的真相源目录 `resources/assets/phonemes/`、`resources/assets/audio_processed/` 按键命名不变，不走内容寻址，不进 PROVENANCE。
- **命名**：`<slug>-<内容 sha256 前 10 位十六进制>.<ext>`，`slug` 为键本身，必须匹配 `^[A-Za-z0-9_-]{1,40}$`，否则导出或工具失败并要求人工命名（当前 300 个无源 blob 的键全部满足，唯一例外 `CELEBRATE_NAT` 无键，slug 固定为 `weekNN`）。`ext` 由 mime 决定。文件名总长小于 64，路径深度固定两层，不含 Windows 保留名、结尾点或空格。
- **内容寻址的后果**：内容变了名字就变。因此被任何清单引用的文件**从构造上不可能被覆盖**；同 slug 不同内容并存是正常状态，旧的由 prune 回收。
- **目标已存在时**（幂等重跑或哈希前缀碰撞）：发布前对已存在文件计算完整 sha256 并核对 mime；完全相同则跳过写入、直接复用；不同则判定为前缀碰撞或仓库损坏，整批失败，绝不覆盖。测试两例：同内容重跑成功且文件字节不变；同名不同字节必须失败。
- **大小写**：同一目录内文件名的小写形式必须唯一（Windows 文件系统不分大小写），冲突即失败；单元测试覆盖。
- **同内容多键**：只落一个文件，slug 取首次出现的键（按周序、声明序、键序），其余键在清单里引用同一路径。
- **PROVENANCE.json**：只记录 adopted 下的媒体文件（`.mp3` / `.png` / `.webp`），不含 README 与自身；单元测试断言"条目集合 == 目录内媒体文件集合"。每个文件**只记首次来源**：sha256、mime、来源（导出：周文件与提交号；工具：工具名、输入路径、日期）、首次采用它的声明名与键（按周序、声明序、键序）。后续别名、跨周复用、素材工具再次引用同一文件都**不改写**已有条目；测试：新增别名后既有条目字节不变。
- **存活真相**：全部周 `manifest.json` 引用的文件才是存活的。`export_embedded_media.py --prune` 删除 adopted 下不被任何清单引用的媒体文件并同步删除其 provenance 条目；prune 之外任何工具不删文件。
- **整批发布**（导出工具与 `embed_assets.py`）：① 全部产物先写到 `resources/adopted/.staging-<随机>/`（与目标同一文件系统）；② 在 staging 内完成全部校验（mime、扩展名、slug、大小写唯一、目标已存在时的哈希核对、清单 schema）；③ 逐文件 rename 到目标位置，只新增不覆盖；④ 原子写 PROVENANCE；⑤ 最后原子写清单。①② 任一失败时仓库内任何已存在文件与清单不变；③ 之后失败只会留下未被引用的新文件，由 prune 回收。无论成功失败，staging 目录最后都删除。
- **音频两个工具的发布**：`build_phonemes.py` 与 `build_audio.py` 在各自目标父目录（`resources/assets/phonemes/`、`resources/assets/audio_processed/`）下建同文件系统的 staging，完成处理与既有自检后 rename 到按键命名的目标文件（允许覆盖同键旧文件，因为这两个目录本来就是"一键一文件"的真相源），最后原子写清单；不写 PROVENANCE。
- **产物侧的名字与仓库侧无关**：`build/media/` 用 `<sha256 前 16 位>.<ext>` 命名，由构建从上述任一目录复制，不解码不重编码；名字随内容变，HTTPS 部署时可给 `media/` 设长缓存、HTML 设短缓存（第 2 期）。构建前把全部引用文件按完整 sha256 分组，同一 16 位前缀对应两个不同完整哈希即失败，禁止覆盖；单元测试构造两个前缀相同的伪文件断言失败。

## 7. 风险与反向理由

- **副机门槛上升。** 不入库后 clone 不能直接打开课件。对策：CI artifact 与 Release 提供下载；副机命令清单第一条固定为 build。
- **交付物从一个文件变成一个目录。** 离线分发要整目录或 zip；单个周文件脱离 `media/` 打不开。对策：Release 附 zip；`--single-file` 留给"只发一周"的场景，但它不是主形态，不设失败护栏。
- **本地文件下的进度共享因浏览器而异。** Chromium 系实测共享，Firefox 预期不共享。对策：README 建议 Chrome 或 Edge；壳按 §3.6 用 `progressDigest` 比对做可见提示；HTTPS 部署后同源，问题消失。
- **桥接从同步调用改为异步消息。** `leave?` 需要回执与超时，`ready` 需要超时兜底，复杂度高于现在的直接调用。对策：协议只有五种消息，全部带会话号与周号并有测试；`event.source` 加会话号替代无法使用的 `origin` 校验；超时不锁死用户。
- **时间与里程碑 2 冲突。** 第 1 期与第 1b 期合计五到六天，落在 09-14 到 09-24；里程碑 2 双字母字位也在 W5 装配前。先做里程碑 2。两者都是第五周装配前的硬截止，本方案不写延期预案（用户 2026-09-07 晚拍板，轻复审 H-3）：赶不上时届时另议，护栏不放宽。
- **插画导出等于最后一次"把 HTML 当源"。** 导出后 `resources/adopted/` 是真相源，`PROVENANCE.json` 记录每个文件从哪个周文件、哪个提交导出；README 声明它是派生媒体而非原始素材。
- **历史重写不可逆。** 引用快照、bundle 可恢复性验证、精确到七个产物名的清单、对照更新先于强推、副机停工窗口五道保护；清理带来的收益只是现有 221 MB，B 之后不再增长，这一条是用户明知代价后的选择。
- **内容寻址命名让清单可读性下降。** 文件名多了 11 个字符的哈希后缀；换来的是"被引用文件不可能被覆盖"这一构造性保证，以及 Windows 下无需处理覆盖冲突。产物侧 `media/` 只有哈希名，可读性靠周文件里的声明键。
- **PNG 不转 webp 的代价。** 50 周 `media/` 约 80 到 105 MB 而不是 25 到 35 MB；不影响任何护栏，只影响 zip 与站点体量。日后若要转，adopted 内容寻址让"新文件并存、旧文件 prune"天然成立，不需要改本方案。
- **单文件形态仍不会变小。** `--single-file` 的周文件体量只由该周引用的媒体决定，复习整段的周可能超过 8 MB；超过时须显式 `--allow-large`，且它不进 Release。
- **文档漂移已在发生。** 三方交接规范 v1.1 与方案 §9.2 都已落后于实作，§6 清单逐文件收口。
