# 工程健康化实施方案 v0.1

## 0. 这份文档管什么

2026-09-06 的目录重构把源码、素材、测试、工具分开了，工程骨架合格。本方案只解决剩下的一个问题：**交付格式被当成了源码格式**，同一段媒体的字节在仓库里存三到四份、生成物随每次改动进 git、媒体声明从产物反向回写。目标是从现在起止住线性膨胀，并让第五周起的每一周只增加"清单 + 新素材"，不再增加全量拷贝。

不在本方案范围：教学内容、第四周试课、第四周设计落差（另案）、后端（六年内不需要）。

## 3. 目标结构

```text
resources/
├─ assets/          原始素材与来源、处理参数（不变）
├─ adopted/         已采用的处理后媒体（新增；第 1 期由导出工具一次性生成，此后由素材工具单向写入）
│  ├─ phoneme-ill/<键>.png   word-ill/<键>.png   wall/<键>.png
│  ├─ books/<书名>/<页键>.png   celebrate/<键>.png
│  └─ words/<词>.mp3          （仅前两周那 34 条无文件源的词音；其余指向 audio_processed）
├─ manifests/       音频生成与处理参数清单（不变）
└─ reference/       仅保留正在引用的候选音（第 0 期裁剪）
frontend/src/
├─ media/weekNN/manifest.json   每周一份，键 → 文件路径 + mime（替代七份 base64 JS）
├─ weeks/、shared/、course.template.html   不变
tools/
├─ build_lessons.py  按清单读文件、编码、原位生成七个声明常量；其余不变
├─ export_embedded_media.py  第 1 期一次性工具，用完保留作历史记录
└─ capture_lesson_media.js   第 1 期删除
根目录 weekNN.html / course.html   不入库；本机 build 生成；CI 产物与 Release 提供下载
```

数据流改为单向：`resources/assets` → 素材工具 → `resources/adopted` + `manifest.json` → `build` → 根目录 HTML → `release` → `dist/`。任何工具不再写 HTML。

清单示例（`frontend/src/media/week04/manifest.json`）：

```json
{
  "schemaVersion": 1,
  "PHONEME_AUDIO": {"s": "resources/assets/phonemes/s.mp3"},
  "WORD_AUDIO":    {"sat": "resources/assets/audio_processed/sat.mp3"},
  "WORD_ILL":      {"cat": "resources/adopted/word-ill/cat.png"},
  "BOOK_IMG":      {"natStand": "resources/adopted/books/nat-naps/natStand.png"}
}
```

跨周共享由清单引用同一文件天然实现；第四周清单全部指向前三周的文件，不新增任何二进制。

## 4. 分期

### 第 0 期：止血（现在，约半天，不碰教学内容与第四周试课）

按顺序执行，每步一个 commit：

1. **快照基线。** `python tools/project.py release` 出一版 dist，把其 `manifest.json` 复制为 `tests/fixtures/baseline_20260907.json` 并入库。它是第 1 期"字节不变"反证的基准。
2. **B 生成物不入库。** `.gitignore` 加 `/week??.html` 与 `/course.html`；`git rm --cached`。`run_checks.py` 的 generated lessons 一步改为先 build 再 `--check`。CI 在 check 前加 `python tools/project.py build`，成功后 `upload-artifact` 上传四周文件与 course.html；打 tag 时创建 Release 附同一批文件。README、development.md、三方交接规范的"clone 即用"改为"先 build"，副机命令清单加 `python tools/project.py build`。
3. **E 体量护栏。** `project.json` 加 `sizeBudgetMB: {"week": 8, "course": 20}`；新增 `tests/unit/test_size_budget.py`，超限即失败；第 1 期完成后下调为 week 6、course 12。
4. **H doctor 版本检查。** `project.py doctor` 输出并校验 node 主版本 ≥ 18，与 CI 的 22 对齐提示。
5. **D 第一步：去二次 base64。** `build_course.py` 的 payload 直接放 HTML 字符串，仅把 `</script` 转义为 `<\/script`；`course.template.html` 去掉 atob 与 TextDecoder。预期 course.html 从 13.6 MB 降到约 10.2 MB。`test_course.py` 回归。
6. **F 移出。** `docs/archive/screenshots/` 整目录移到 `E:/worklog/english-for-child/archive/screenshots/`，原位留一行 README 指路；`resources/reference/OpenLearn_Phonics_Audio/` 移到同处；`resources/assets/phonemes/source-library/` 的 TESSA 与 margo 两包保留（音素来源正在引用）。更新 architecture.md、development.md、第四周设计文档中的路径。
7. **G 清理历史。** 放在本期最后，只重写一次：
   - 全库备份：`git bundle create E:/_backups/english_for_child_pre-rewrite_20260907.bundle --all`。
   - 删除本地遗留分支 `backup/pre-reword`、`rewrite`、`v3-p0` 与远端 `v3-p0`；它们会让旧对象存活。
   - `pip install git-filter-repo`；先用 `git log --all --diff-filter=A --name-only -- '*.html'` 列出历史上所有产物文件名（含 week01-v3.html 等旧名），再 `--invert-paths` 清除；同批清除 `docs/archive/screenshots/` 与 `resources/reference/`。
   - 强推 main；副机重新 clone；filter-repo 生成的 commit-map 存为 `docs/项目记忆/历史重写对照_20260907.md`，归档里 12 个可解析的 commit 号与 2 份含 Claude-Session 基准的文件按对照表更新。
   - 预期 `.git` 从 221 MB 降到 40 MB 左右；这是估计，以实测为准。

### 第 1 期：媒体清单化（W5 装配前，建议 09-14 到 09-20，一到两天加 codex 审）

1. **导出。** 新工具 `tools/export_embedded_media.py`：读第 0 期基线对应的构建产物，逐声明逐键：有逐字节相同文件的写路径，没有的导出到 `resources/adopted/` 并写路径；生成四周 `manifest.json`。

## 6. 风险与反向理由

- **副机门槛上升。** 不入库后 clone 不能直接打开课件。对策：CI 产物与 Release 提供下载；副机命令清单第一条固定为 build。
- **插画导出等于最后一次"把 HTML 当源"。** 导出后 `resources/adopted/` 是真相源，README 与 `phonemes/README.md` 同款声明要写清；embed_assets 的规格化步骤此后写 adopted 而非 HTML。
- **历史重写不可逆。** bundle 备份先行；远端旧分支处置要与副机确认；所有 clone 必须重建，任何未推送的本地提交会丢。清理带来的收益只是现有 221 MB，B 之后不再增长，这一条是用户明知代价后的选择。
- **护栏误报。** 小书多的周可能触线；触线时先看是不是重复媒体，再决定放宽阈值。
- **时间。** 第 1 期与第五周里程碑 2 都落在 09-14 到 09-27 之间；第 0 期半天可在本周内完成，第 1 期若与里程碑 2 抢时间，里程碑 2 优先，第 1 期顺延到 W5 之后，代价是第五周再多一份全量拷贝。
- **文档漂移已在发生。** 三方交接规范 v1.1 与方案 §9.2 都已落后于实作，借本方案一并升版。
