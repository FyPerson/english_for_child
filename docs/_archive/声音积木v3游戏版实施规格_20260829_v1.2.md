## 2. 播放层改造（Voice → WordAudio）

### 2.1 异步契约（二审 H-3）

`WordAudio.play(key, opts)` 为唯一单词/句子播放入口，返回 **Promise，永不 reject**，resolve 为：

```js
{ status: 'ended' | 'failed' | 'cancelled' | 'blocked' }
```

- `ended`：完整播完。**含系统 TTS 兜底成功的情形**（R-2）：承诺音源失败后若检测到英文语音则尝试兜底，兜底完整播完 → 仍 resolve `ended`（对调用方等价成功）；兜底失败或无英文语音 → `failed`。play() 在兜底结束后才最终 resolve，调用方全程只等一个 Promise。
- `failed`：缺键 / 解码失败 / play() 被拒 / **8 秒超时兜底**（防 ended 事件丢失挂死调用方），且 TTS 兜底也未成功。触发失败提示条（§2.3）。
- `cancelled`：被更新的播放请求或切页打断。不触发提示条。
- `blocked`：黑名单守卫拦截（§2.5），console.warn，无任何 UI，**不做 TTS 兜底**。
- **递增令牌**：模块内 `playSeq`，每次 play 自增。旧请求的回调凭令牌失效——旧 Promise 立即以 `cancelled` resolve，其后续 UI 操作一律不执行。
- `opts.rate`：playbackRate（慢速 0.8 复用同一 clip，不生成慢速版音频）。

**结果处理统一约定（所有调用方，R-2）**：`ended` → 推进（起作答窗 / 接第二遍 / 播 phrase）；`cancelled` / `blocked` → 不推进、无 UI；`failed` → 调用方进入 audioFailed 态（见 §2.3）。各游戏不得自行解释。

### 2.2 仲裁

全局唯一 `Audio.stopAll()` 入口：停止内嵌音频、系统 TTS、**音素真人音**，并使未决 play 令牌失效。**Phone.say（六音素）、WordAudio.play、speakFallback 三个发声方都在开播前调用 stopAll**（R-9：D3 的"不动"仅指六个真人音资产与 data-sayph 教学行为不变，Phone.say 的实现必须接入仲裁）。切换页面/游戏时调用 stopAll（挂在现有 `clearPageTimers()` 同一节点，week01-v2.html:1473）。首次播放由用户点击触发（浏览器手势策略），页面不自动出声；游戏内"自动播题"必须发生在"开始本轮"的用户手势之后（§4.1）。

### 2.3 失败可见与续接协议（R-2）

`failed` → 页面顶部中文提示条「声音没放出来，点这里再试一次」。**提示条持有本次失败的 retry continuation**：重试 = 重新执行调用方注册的重播流程（如 G1 重播本题并重新起窗），不是裸播 key；切页或任何新播放使 continuation 失效（令牌），提示条随之消失。

**题目型游戏（G1/G3）的失败口径**：failed 题**停留在本题**——不判分、不推进，重试成功后正常起作答窗，可无限重试；每轮常驻「重新开始这一轮」入口。一轮判分分母恒为全部题数（G1=8、G3=10），通关线唯一（8 对 6 / 10 对 7）。音频彻底不可用属 D10 级故障，不在游戏内解决。

系统 TTS 兜底语义已并入 §2.1（兜底成功=ended）。兜底用 ≤10 行极简 `speakFallback(text)`，**不保留 v2 Voice 模块**（含 kick/setTimeout 时序 hack 与 `sayParts`——grep 确认全文无调用点，week01-v2.html:820 仅定义）。

**回合状态机（二审 M-1 + R-2）**：

| 状态 | 进入条件 | 行为 |
|---|---|---|
| idle | 进入游戏 | 显示口令 +「开始这一轮」按钮（用户手势，满足播放策略） |
| playing | 开轮 / 上一题结束 | 自动播词，播放期锁答 |

### 4.6 G6 计时闪卡（增强，P1；R-1 重写）

第一周有**两个** timed flash 组（v2 实测 Day6，week01-v2.html:1135–1147），度量不同，组键为静态常量（随 block 数据声明 `recKey`，**不用运行时 uid 做持久化键**）：

| 组 | recKey | v2 玩法（不变） | metric | 成绩取值时点 |
|---|---|---|---|---|
| Day6 六音快闪 | `flash_sounds` | 秒表：六个音过一遍看多少秒 | `elapsed`（秒，**小优**，须 > 0） | 家长点「停」时锁定本次秒数 |
| Day6 词卡 30 秒挑战 | `flash_words` | 30 秒内能读出几个，读错不停跳过继续 | `count`（张，**大优**） | 开始后 **30 秒自动停表**（对 v2 的增强），成绩 = 期间前进的张数 |

- 计数语义与 D5 的边界：屏幕只记"翻过几张"，是否真读出仍由家长控制翻卡节奏（沿用 v2 人工监督语义，屏幕不判"读出"）；本纪录不进战利品墙。
- 存储：`games.flash[recKey] = {metric, value}`；比较用统一 `isBetter(metric, a, b)`（elapsed 小优 / count 大优），不做 itemSetVersion。
- 反馈：破纪录：彩带 + Nat 庆祝；未破：显示本次与最好成绩。中途退出不记录。
- 边界：exam step 内不引入任何计时/纪录机制（§3.1）。

## 6. 状态模式

### 6.1 schema（二审 H-4/H-5 落定）

```js
state.games = {
  grab:  { s: {best: 0}, a: {best: 0} },   // count 大优，0–8 整数
  doors: { best: 0 },                       // count 大优，0–10 整数
  flash: { /* recKey: {metric:'elapsed'|'count', value:Number} */ },
  confirms: { /* 词: {g2:Bool, g4:Bool, g5:Bool} —— 按词×来源 */ }
}
```

- **trophies 派生不存储**：`derivedTrophies() = confirms 中任一来源为 true 且非保留词的词`。
- **确认/撤销幂等**：`confirmWord(w, src)` → 置 true（保留词直接拒绝，§2.5 入口 5）；`unconfirmWord(w, src)` → 置 false，**只影响该来源**。重复调用无副作用；全来源 false 的词从战利品墙消失。
- KEY 不变（`soundblocks-w1-v1`）；`state.days` 沿用 v2 逻辑不动。

### 6.2 读取清洗（二审 M-3 + R-6，字段级 + 范围）

| 字段 | 类型规则 | 范围规则（R-6，非法→恢复默认或删除） |
|---|---|---|
| `games` / `flash` / `confirms` 容器 | 仅接受**非 null、非数组的普通对象**，否则整体重建默认（`games` 坏 → 重建且**不动 days**） | — |
| `grab.*.best` | 数字 | 0–8 整数，否则置 0 |
| `doors.best` | 数字 | 0–10 整数，否则置 0 |
| `flash` 每键 | 键 ∈ {flash_sounds, flash_words}，值形如 {metric, value} | metric 与 recKey 声明一致；elapsed 须 > 0，count 须为 0–组容量整数；非法删该键（**不得写成 0 占位**，避免 elapsed 永不可破） |

## 10. 构建管线契约：tools/build_audio.py（二审 H-2 + R-3/R-8）

**输入**：`tools/audio_manifest.json`（§1 单一权威数据源）、`assets/audio_raw/`、week01-v3.html。
**失败行为**：任一自检不过 → **非零退出且不写任何输出**；输出为原子替换（先写临时文件再覆盖）。

自检七项：

1. **唯一性断言**：manifest 键去重后条数 == 条目数 == 56；文件名无冲突。
2. **黑名单断言**：RESERVED 五词不出现在 manifest 或 WORD_AUDIO。
3. **引用覆盖（R-3 改写）**：**从 v3 源码的数据字面量层提取运行时键**，提取源清单：`SOUNDS[*].demo`、DAYS 中 `words/sight/sentences` 块的 items、词卡墙词表与 `WALL_HINT`、`BOOK.pages[].line`（规范化后）、G1/G3/G4 题库常量、G5 白名单。约束：这些数据结构在 v3 中**保持可正则提取的规范字面量形状**（编码时与提取正则一起冻结，改结构必须同步改提取器——提取器取不到任何键时按失败处理，防正则静默失效）。断言：提取全集 ⊆ manifest 键，且 manifest 键 0 缺失 mp3。运行时兜底：play 缺键 → failed 提示条可见（§2.1）；人工兜底：验收 #3 全量点检。
4. **黑名单渲染检查**：RESERVED 五词不出现在 ③ 的任何提取源（exam 静态卡不在提取源内，天然通过）。
5. **题库断言**：G1 两轮答案键（正例+负例）、G3 词对、G4 词表 ⊆ manifest 键且不含 RESERVED；G5 白名单 == A 组 18 词。
6. **音频完整性（R-8 可判定）**：每条 mp3 可解码、时长 > 0；**后处理由本脚本强制执行**（§1 参数：-40dBFS 裁静音、首尾各 ≤ 80ms、峰值归一 -3dBFS ± 1dB），自检验证处理后的测量值在容差内。
7. **体积报告**：注入后 HTML 增量输出到 stdout，> 1.2MB 时警告（不阻断，人工判断）。

生成脚本 `tools/gen_audio.py`（已建，断点续跑）与本脚本分工：生成原始 clip / 后处理+校验+注入。生成后**逐条人工听检**仍是必经步骤（§8 P0）。
