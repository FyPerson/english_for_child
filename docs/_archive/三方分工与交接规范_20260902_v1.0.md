| | 主机 | 副机 |
|---|---|---|

## 1. 三方角色

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **用户** | 拍板；上课与回收数据（周检、月测、总表）；人耳听检（音素与单词发音对不对，机器验不了）；两台电脑之间的 push / pull；操作 GPT 会话并把产物放进仓库 | 不改课件 HTML 正文；不在两台电脑同时改同一周的文件 |
| **Claude（主机）** | 课程设计与每周数据层；引擎升级与里程碑；装配；音频 manifest 与注入；插画提示词文档；校验、冒烟、codex 审；提交；文档维护 | 不出图；不替用户做听检结论；不在副机上工作 |
| **GPT（副机）** | 按提示词文档出图；按 §5 规则调发音（已验证）；按需回答用户关于课件使用的问题 | 不改 HTML；不改工具处理链和自检；不写数据层（2026-09-02 定：数据层归 Claude）；不改风格前缀；不发明新块类型、新常量、新文件名规则 |

一句话：**Claude 出内容和结构，GPT 出图和调音，用户拍板和听检，仓库是唯一的交接载体。**

**并行规则**：主机做第 N+1 周的步 1 到 5 时，副机可以同时做第 N 周的步 6、7，因为碰的是不同周的文件。

## 4. GPT 工作包

### 4.1 配图包（每次开新对话固定投喂）

给这些，只给这些：

1. 本周插画提示词文档（`docs/插画生成提示词_第N周_*.md`）
2. 三张风格参考图：`assets/word-cards/pin.png`、`assets/phoneme-mnemonics/s-snake.png`、`assets/wall-nat/natSit.png`
3. 本周角色定妆图（若提示词文档要求先出，则第一步就是出它）
4. 下面的开场提示词

**不给**：任何 HTML、整个仓库、工具脚本。给了整仓库它大概率会去改 HTML。

**开场提示词**（用户复制到 GPT 会话第一条）：

> 你是这个儿童英语课件项目的插画师。项目风格已经定稿，你的任务只有一件：按我给你的提示词文档，逐张生成透明底 PNG，1024×1024，画面里不能有任何文字或字母。
> 规则：文档里的"通用风格前缀"一个字都不能改，每张图都要带；先看我附的三张参考图对画风；文档说"先出角色定妆图"的，先出定妆图并等我确认再出场景；文档标"建议跳过"的词不要画。
> 输出：每张图告诉我它对应的文件名（等于文档表格里的 art 键），我会按这个名字保存。不要给我改代码、改文档、改文件名规则的建议；有问题直接问我。

### 4.2 发音包（用户听检后需要调整时）

给这些：

1. 本周 manifest：`tools/audio_manifest_wN.json`
2. `docs/声音积木周课件设计规范_20260831_v1.0.md` 的 §6 和 §11（音频规则、词尾爆破怎么查怎么修）
3. `assets/phonemes/README.md`（只在涉及音素录音时给）
4. 待修清单：哪些键、听起来哪里不对（例如"milk 的 k 没了""sad 词尾太重"）

**开场提示词**：

> 你是这个项目的音频调整助手。项目有一条固定管线：`tools/gen_audio.py` 用 edge-tts 生成、`tools/build_audio.py` 裁静音归一并注入课件。你只能通过改 manifest 里的逐条参数来调整：`voice`、`rate`、`silence_threshold_db`、`manual_trim`，然后用 `python tools/gen_audio.py --manifest <文件> --force --key "<键>"` 局部回炉、用 `python tools/build_audio.py --manifest <文件> --target weekNN.html` 注入。
> 不能做的事：改声线（单词句子 en-US-JennyNeural，小书 en-US-EmmaNeural）、改处理链常量、改七项自检、给单个音素用 TTS、直接编辑 HTML。
> 每次改完把 build_audio 的自检输出和你改了哪些键、哪些参数、为什么，整理成一段话给我，我要写进提交说明。

### 4.3 回传验收（谁在主机跑步 8 谁查）

| 项 | 怎么查 | 不过怎么办 |
|---|---|---|
| 文件名 = art 键，落在正确子目录 | `python tools/embed_assets.py --target weekNN.html --assets assets/weekNN --dry-run`：覆盖数与孤儿图 | 孤儿图改名或删除；缺图允许，走守卫 |
| 透明底、主体完整不出血、无文字 | 打开看；`embed_assets.py` 规格化后再看 192px 缩略 | 退回 GPT 重出该张 |
| 画风与第一周一致 | 与三张参考图并排看：描边粗细、平涂、无渐变、色板 | 退回并强调附参考图 |
| 抽象词未画 | 对照提示词文档"建议跳过"列表 | 删除多余图 |
| 庆祝图 384px | 文件尺寸 | 退回 |
| 音频：七项自检全绿、tripwire 未被改 | `python tools/build_audio.py --manifest ... --no-inject`；`git diff tools/build_audio.py` 应为空 | 处理链被改则回滚脚本，只保留 manifest 改动 |
| 音频：词尾爆破 | 规范 §6.1 的 RMS 剖面查法 | 加 `manual_trim` 回炉 |
| 音频：人耳听检 | 用户逐个听；结果记总表 | 退回 §4.2 |

## 5. 发音规则（两边通用）

第二周的发音调整已由 GPT 侧在这条管线上完成并被用户认可，因此发音**两边都可以做**，规则相同：

- **只改 manifest 的逐条参数**：`voice`（仅允许在 Jenny 与 Emma 之间按用途选）、`rate`、`silence_threshold_db`（-90 到 -20）、`manual_trim`。
- **局部回炉用 `--key`**，不用 `--force` 整批重生成，避免覆盖人工修过的原音。
- **不改**：处理链常量、七项自检、提取源注册表、注入锚、`SOURCE_SPECS` 冻结计数。计数对不上是 tripwire 在工作，先查数据形状再决定是否更新 manifest 的冻结值，并在提交说明里写明。
- **音素永远真人录音**：新音素按 `assets/phonemes/README.md` 加，署名进页脚；没有录音就走守卫（换元素，不留哑巴按钮）。
- **听检是用户的活**，机器只验响度、时长、静音；每周听检结果记入总表，作为下次是否调整的依据。
- **提交说明必须写**：改了哪些键、哪些参数、为什么、自检结果。

## 6. 换电脑衔接

**开工前（任一台电脑）**：

1. `git pull`，`git status -sb` 确认与 origin 同点、工作区干净。
2. 跑 `docs/项目记忆/换机验证清单.md`（第一次换机全五关；之后至少第 1、2 关）。
3. 读 `docs/项目记忆/README.md` §1"现在到哪一步"和 §4"当前阻塞"。当前在哪个 commit 用 `git log --oneline -1` 看，不信任何文档里写死的值。

**离开前（任一台电脑）**：

1. 该提交的都提交，`git status` 干净，`git push`。
2. 在 README §1 更新一行"现在到哪一步"（只写状态，不写 SHA）。
3. 若这台电脑上有半成品不想提交：写进 README §4"当前阻塞"，说明在哪台电脑、什么状态。

**分支与冲突**：只用 `main`，不建长期分支。同一周的文件同一时间只在一台电脑改；配图与主机装配并行时按 §3"并行规则"错开周次。真冲突了，HTML 以主机版本为准，PNG 与 mp3 以副机版本为准，manifest 手工合并。

**不跨机的东西**：Claude 本机记忆（真相在仓库 `docs/项目记忆/`）；`tmp/`（已忽略，codex 运行产物）；`.claude/settings.local.json`（已忽略）。

**Claude Code 在新机器上开工**：仓库自带的 `/handoff`、`/tidy-docs` 会自动加载；第一条动作是读 README，不是读会话历史。

## 7. 冲突与优先级

- **真相源优先级**：上一周定稿 HTML 的实作 > 周课件规范 > 课程方案 > 本文 > design-doc。
- **GPT 的产物与规范冲突**：规范赢。GPT 提的"优化建议"一律先记成 issue 由用户拍板，不直接落地。
- **谁能改工具**：只有 Claude 改处理链、校验器、注入脚本；GPT 与用户只改 manifest 参数和素材文件。
- **谁能改文档**：本文、周课件规范、课程方案由 Claude 改并走版本号；提示词文档每周一份不回改旧周；README 两边都可以改 §1、§4 的状态行。
