# 工程健康化实施方案 v0.2

## 0. 这份文档管什么

2026-09-06 的目录重构把源码、素材、测试、工具分开了，工程骨架合格。本方案只解决剩下的一个问题：**交付格式被当成了源码格式**，同一段媒体的字节在仓库里存三到四份、生成物随每次改动进 git、媒体声明从产物反向回写。目标是从现在起止住线性膨胀，并让第五周起的每一周只增加"清单 + 新素材"，不再增加全量拷贝。

不在本方案范围：教学内容、第四周试课、第四周设计落差（另案）、后端（六年内不需要）。

## 3. 目标结构与契约

### 3.1 目录

```text
resources/
├─ assets/          原始素材与来源、处理参数（不变）
├─ adopted/         已采用的处理后媒体（新增；第 1 期由导出工具一次性生成，此后由素材工具单向写入）
│  ├─ phoneme-ill/  word-ill/  wall/  books/<书键>/  celebrate/  words/
│  ├─ PROVENANCE.json   每个文件的 sha256、mime、导出来源（周文件与提交号）、导出日期
│  └─ README.md         声明：这是"采用的派生媒体"，原始素材与处理参数在 assets/
├─ manifests/       音频生成与处理参数清单（不变）
└─ （reference/ 整目录移出仓库，见第 0 期第 6 步）
frontend/src/
├─ media/weekNN/manifest.json   每周一份（替代七份 base64 JS）
├─ weeks/、shared/、course.template.html
tools/
├─ build_lessons.py   识别 @media 标记，按清单读文件、编码、原位生成声明
├─ export_embedded_media.py   第 1 期一次性工具，用完保留作历史记录
└─ capture_lesson_media.js    第 1 期第 6 步删除
根目录 weekNN.html / course.html   不入库；本机 build 生成；CI 产物与 Release 提供下载
```

数据流单向：`resources/assets` → 素材工具 → `resources/adopted` + `manifest.json` → `build` → 根目录 HTML → `release` → `dist/`。任何工具不再写 HTML。

### 3.2 媒体清单 schema

```json
{
  "schemaVersion": 1,
  "week": 4,
  "declarations": {
    "PHONEME_AUDIO": {"s": {"path": "resources/assets/phonemes/s.mp3", "mime": "audio/mpeg"}},
    "WORD_AUDIO":    {"sat": {"path": "resources/assets/audio_processed/sat.mp3", "mime": "audio/mpeg"}},
    "PHONEME_ILL":   {"snake": {"path": "resources/adopted/phoneme-ill/snake.png", "mime": "image/png"}},
    "WORD_ILL":      {},
    "WALL_ILL":      {},
    "BOOK_IMG":      {},
    "CELEBRATE_NAT": {}
  }
}
```

规则，任一违反构建失败：

1. 七个声明键必须全部出现，允许空对象；空对象生成 `const NAME = {};`。
2. `path` 相对仓库根，必须解析到 `resources/` 之下，禁止 `..` 与绝对路径；文件必须存在。
3. `mime` 只允许 `audio/mpeg`、`image/png`、`image/webp`；扩展名必须与 mime 一致（`.mp3` / `.png` / `.webp`）。
4. 同一文件可被多个键、多个周引用（别名与跨周共享）；同一声明内键不得重复。
5. 键顺序以 JSON 文件中的顺序为准，生成声明按此顺序输出；构建不排序。
6. 生成格式固定为 `const NAME = {\n  '<键>': 'data:<mime>;base64,<b64>',\n  ...\n};`，键一律用单引号包裹，与旧三种注入格式无关。

模板侧把七个 `<!-- @include media/weekNN/<name>.js -->` 改为同位置的 `<!-- @media weekNN NAME -->`，位置不动。校验器 `tools/validation/` 增加 manifest 校验，`tests/unit/test_media.js` 改为：清单每键文件存在、mime 与扩展名一致、内嵌字节的 sha256 等于文件 sha256；引用覆盖检查与跨周音素一致检查保留。

### 3.3 基线与"字节不变"的定义

基线文件 `tests/fixtures/baseline_20260907.json`（入库）：

```json
{
  "schemaVersion": 1,
  "takenAt": "2026-09-07",
  "sourceCommit": "<第 0 期第 1 步时的 HEAD>",
  "weeks": {"week01.html": {"sha256": "...", "skeletonSha256": "...", "media": {"PHONEME_AUDIO": [["s", "audio/mpeg", "<sha256>"]]}}},
  "course": {"beforeStep5": "<sha256>", "afterStep5": "<第 0 期第 5 步后回填>"}
}
```

- `sha256`：整文件哈希，用于第 1 期导出前的准入校验。
- `skeletonSha256`：把七个声明整段替换为占位符后的哈希，用于第 1 期验收"非媒体部分一字未变"。
- `media`：每声明按键序的 `[键, mime, 解码字节 sha256]` 列表，用于第 1 期验收"每键媒体与键序一字未变"。
- 基线由 `python tools/project.py build` 在干净工作区、记录的提交号上生成，不依赖 `dist/`（`dist/` 不入库、不随 clone 保留）。
- course.html 只记录第 5 步前后两个哈希，**不参与第 1 期比对**。

第 1 期"字节不变" = 四个周文件的 `skeletonSha256` 与 `media` 与基线完全相等。这比整文件哈希弱的只有一处：声明文本的写法，它由 §3.2 第 6 条固定为一种。

### 3.4 检查契约（`check`）

生成物不入库后，"过期生成物"不再可能出现在版本库里。`check` 改为：

1. `build`：从源码构建，写根目录。
2. `reproducible build`：再构建一次到临时目录，五个文件哈希必须与第 1 步相同；不同即失败。`build_lessons.py --check` 保留为此用途。
3. 其余作业不变：目录布局、构建边界、测评契约、媒体、浏览器回归。

`--quick` 同样先 build。README、development.md、CI 三处的命令说明同步。

### 3.5 体量护栏

`project.json` 增加：

```json
"sizeBudgetMB": {"week": 8, "course": 20}
```

- 计算对象：构建后根目录每个 `weekNN.html` 与 `course.html` 在磁盘上的字节数；`index.html` 不计。
- 单位：十进制 MB，1 MB = 1 000 000 字节。
- 判定：字节数 **大于** 预算即失败；等于通过。
- `tests/unit/test_size_budget.py` 从 `project.json` 读预算，并含一个"伪造超限文件必须失败"的反例。
- 第 1 期完成后把预算改为 week 6、course 12，作为第 1 期验收项之一。

### 3.6 合并入口 payload（第 0 期第 5 步）

- `build_course.py`：`data['html']` 直接放周 HTML 字符串，不再 base64；`json.dumps` 之后对整段序列化结果做两处替换：`</` 改为 `<\/`，`<!--` 改为 `<\!--`。这两处在 JSON 字符串里是等价转义，浏览器 `JSON.parse` 后得到原文。
- `course.template.html`：`frame.srcdoc = course.weeks[week-1].html`，删除 atob 与 TextDecoder。
- `tests/browser/test_course.py`：增加断言，payload 能被 `JSON.parse`，且解析后的周 HTML 含 `</script>` 与中文。
- 基线回填 `course.afterStep5`。预期 course.html 约 10.2 MB。

### 3.7 CI 与 Release

`.github/workflows/check.yml` 改为两个 job：

| job | 触发 | 步骤 | 权限 |
|---|---|---|---|
| check | push、pull_request、workflow_dispatch | 装依赖 → `project.py check` → 成功时 `upload-artifact` 上传 `week??.html`、`course.html`、`manifest.json`；失败时上传截图 | `contents: read` |
| release | `push` 到 `v*` tag，`needs: check` | 下载 check 的 artifact，用同一批字节创建 GitHub Release 并附上 | `contents: write`，仅此 job |

验收：push、pull_request、tag 三种触发各跑一次；下载 artifact 后逐文件 sha256 与本机同一提交构建结果相同。

### 第 2 期：合并入口薄壳分流（域名确定后）

设计：`course.template.html` 在 http 或 https 下 `fetch('weekNN.html')` 后塞入 srcdoc；file 下沿用内嵌 payload。依赖三个假设，第 2 期开工前逐一实测而非默认成立：

| 假设 | 依据 | 验证方式 |
|---|---|---|
| srcdoc iframe 继承父页源 | HTML 规范：无 sandbox 的 srcdoc 文档与父页同源 | Windows Chrome 与 Edge 的 file 与 http 各测一次父子页读写同一 localStorage 键 |
| file 下父子页共享 localStorage | 因浏览器而异，README 已注明 | 同上，记录各浏览器结果 |

## 7. 风险与反向理由

- **副机门槛上升。** 不入库后 clone 不能直接打开课件。对策：CI artifact 与 Release 提供下载；副机命令清单第一条固定为 build。
- **插画导出等于最后一次"把 HTML 当源"。** 导出后 `resources/adopted/` 是真相源，`PROVENANCE.json` 记录每个文件从哪个周文件、哪个提交导出；README 声明它是派生媒体而非原始素材。
- **历史重写不可逆。** 硬门槛、bundle 可恢复性验证、副机停工窗口三道保护；清理带来的收益只是现有 221 MB，B 之后不再增长，这一条是用户明知代价后的选择。
- **护栏误报。** 小书多的周可能触线；触线时先看是不是重复媒体，再决定放宽阈值。
- **时间。** 第 1 期与第五周里程碑 2 都落在 09-14 到 09-27 之间；第 0 期一到一个半天可在本周内完成，第 1 期若与里程碑 2 抢时间，里程碑 2 优先，第 1 期顺延到 W5 之后，代价是第五周再多一份全量拷贝。
- **文档漂移已在发生。** 三方交接规范 v1.1 与方案 §9.2 都已落后于实作，§6 清单逐文件收口。
