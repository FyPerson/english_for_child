# 工程健康化实施方案 v0.4

## 0. 这份文档管什么

2026-09-06 的目录重构把源码、素材、测试、工具分开了，工程骨架合格。本方案只解决剩下的一个问题：**交付格式被当成了源码格式**，同一段媒体的字节在仓库里存三到四份、生成物随每次改动进 git、媒体声明从产物反向回写。目标是从现在起止住线性膨胀，并让第五周起的每一周只增加"清单 + 新素材"，不再增加全量拷贝。

不在本方案范围：教学内容、第四周试课、第四周设计落差（另案）、后端（六年内不需要）。

### 3.2 媒体清单 schema

```json
{
  "schemaVersion": 1,
  "week": 4,
  "declarations": {
    "PHONEME_AUDIO": {"s": {"path": "resources/assets/phonemes/s.mp3", "mime": "audio/mpeg"}},
    "WORD_AUDIO":    {"sat": {"path": "resources/assets/audio_processed/sat.mp3", "mime": "audio/mpeg"}},
    "PHONEME_ILL":   {"snake": {"path": "resources/adopted/phoneme-ill/snake-3fa9c2b1e0.png", "mime": "image/png"}},
    "WORD_ILL":      {},
    "WALL_ILL":      {},
    "BOOK_IMG":      {},
    "CELEBRATE_NAT": {"path": "resources/adopted/celebrate/week04-8c1d0e77aa.png", "mime": "image/png"}
  }
}
```

规则，任一违反构建失败：

1. 顶层只允许 `schemaVersion`、`week`、`declarations` 三个键；`declarations` 必须恰好含七个声明名，不多不少；声明内条目只允许 `path`、`mime` 两个字段。
2. 六个对象声明的值是键值映射，允许空对象；`CELEBRATE_NAT` 的值是单个 `{path, mime}`，不允许空。
3. 键必须匹配 `^[A-Za-z0-9 ,.!?-]{1,80}$`（四周 652 个现有键全部满足）；JSON 用拒绝重复键的方式解析（Python `object_pairs_hook`），同一声明内重复键即失败。
4. `path` 是仓库相对的 POSIX 路径：只允许 `/` 分隔，出现反斜杠即失败；禁止 `..` 与绝对路径；`realpath` 解析后必须位于真实的 `resources/` 树内（符号链接逃逸即失败）；目标必须是普通文件，目录或不存在即失败。
5. `mime` 只允许 `audio/mpeg`、`image/png`、`image/webp`；扩展名必须与 mime 一致（`.mp3` / `.png` / `.webp`）。
6. 同一文件可被多个键、多个声明、多个周引用（别名与跨周共享）。
7. 键顺序以 JSON 文件中的顺序为准，生成声明按此顺序输出；构建不排序。
8. 生成文本固定：对象声明为 `const NAME = {` 一行、每键一行 `  '<键>': 'data:<mime>;base64,<b64>',`、末行 `};`；空对象为单行 `const NAME = {};`；字符串声明为单行 `const CELEBRATE_NAT = 'data:<mime>;base64,<b64>';`。一律 LF、无注释、无其他常量。这三种写法都能被 `tools/validation/load_data.js` 的 `declaration()` 解析（多行以 `^\s*[}\]];` 结束、单行以首个 `;` 结束），单元测试用 `declaration()` 解析七类声明各一次，并含一个"缺少结尾 `};`"的截断反例。

模板侧把七个 `<!-- @include media/weekNN/<name>.js -->` 改为同位置的 `<!-- @media weekNN NAME -->`，位置不动。构建规则：`@include media/` 与 `@media` 在第 1 期并存期可以同时被识别，但**同一个声明名在一个模板里只能出现一次**；构建先枚举模板里全部 `@media` 与 `@include media/` 标记，按声明名计数，出现两次、出现未知指令或未知声明名即失败。反例测试：缺声明、多余顶层键、重复键、非法键字符、反斜杠路径、目录路径、符号链接逃逸、`..` 路径、未知 mime、扩展名不符、文件缺失、同名声明出现两次、截断声明。

### 3.3 基线与"字节不变"的定义

基线文件 `tests/fixtures/baseline_20260907.json`（入库），四周齐全：

```json
{
  "schemaVersion": 1,
  "takenAt": "2026-09-07",
  "sourceCommit": "<40 位十六进制 SHA-1>",
  "toolVersions": {"python": "3.12.x", "node": "v22.x.y", "hash": "sha256"},
  "weeks": {
    "week01.html": {
      "sha256": "...",
      "skeletonSha256": "...",
      "declarationOrder": ["PHONEME_ILL", "BOOK_IMG", "WALL_ILL", "WORD_ILL", "CELEBRATE_NAT", "WORD_AUDIO", "PHONEME_AUDIO"],
      "media": {"PHONEME_AUDIO": [["s", "audio/mpeg", "<sha256>"]], "CELEBRATE_NAT": [["", "image/png", "<sha256>"]]}
    },
    "week02.html": {}, "week03.html": {}, "week04.html": {}
  },
  "course": {"beforeStep5": "<sha256>", "afterStep5": "<第 0 期第 5 步后回填>"}
}
```

- **生成入口**：新增一次性命令 `python tools/project.py baseline --create`。前置：工作区与 index 干净；目标 fixture 不存在，已存在则拒绝，除非显式 `--force`。命令内部执行 build 并记录 HEAD。**普通 `build` 与 `check` 只读取和比较基线，绝不写它**；单元测试断言 build 与 check 的代码路径不引用写入基线的函数。
- `sha256`：整文件哈希，用于第 1 期导出前的准入校验。
- `skeletonSha256`：先用正则枚举全文所有 `^const <NAME> = ` 起点，七个声明名各必须恰好一次，否则失败；再用 `load_data.declaration()` 确定每段结束边界；每段替换为固定占位符 `/*@MEDIA <NAME>@*/` 后取哈希。
- `declarationOrder`：七个声明在文档中的出现顺序。
- `media`：每声明按键序的 `[键, mime, 解码字节 sha256]` 列表；字符串声明的键记为空串。
- 可证伪测试四类：重复声明必须失败；声明换序必须改变 `declarationOrder`；缺结尾必须失败；声明之外的普通文本改一个字符必须改变 `skeletonSha256`。
- course.html 只记录第 5 步前后两个哈希，**不参与第 1 期比对**。

第 1 期"字节不变" = 四个周文件的 `skeletonSha256`、`declarationOrder`、`media`（键数、键序、mime、字节）与基线完全相等。它比整文件哈希弱的只有一处：声明文本的写法，已由 §3.2 第 8 条固定。

### 3.4 构建与检查契约

- `build_lessons.py` 新增 `--output-dir <目录>`：把五个产物写到指定目录而不是根目录；不传则写根目录。原 `--check` 删除。
- `check` = ①`build`（写根目录）②`build --output-dir <临时目录>` 后逐文件比较五个 sha256，不同即失败（可重现构建）③其余作业：目录布局、构建边界、测评契约、媒体、浏览器回归。fresh clone 上 ① 先写出根目录文件，后续作业读它们。
- `release` = `check` 通过后直接 `package` 根目录产物到 `dist/`，**不再构建第三次**。`serve` 同理。
- `--quick` 同样执行 ① ②。README、development.md、CI 三处命令说明同步。

### 3.5 体量护栏

`project.json` 增加：

```json
"sizeBudgetMB": {"week": 8, "course": 20}
```

- 计算对象：构建后根目录每个 `weekNN.html` 与 `course.html` 在磁盘上的字节数；`index.html` 不计。
- 单位：十进制 MB，1 MB = 1 000 000 字节。
- 判定：字节数 **大于** 预算即失败；等于通过。
- `tests/unit/test_size_budget.py` 从 `project.json` 读预算，并含一个"伪造超限文件必须失败"的反例。
- 第 1 期完成后把预算改为 week 6、course 12；第 1 期验收脚本断言 `sizeBudgetMB` 等于该值。

### 3.6 合并入口 payload（第 0 期第 5 步）

- `build_course.py`：`data['html']` 直接放周 HTML 字符串，不再 base64；`json.dumps(..., ensure_ascii=False)` 之后把序列化结果里的每个 `<` 替换为六个字符 `\u003c`（反斜杠、u、0、0、3、c）。JSON 语法本身不含 `<`，所以替换只落在字符串内，且 `\u003c` 是合法 JSON 转义；它同时覆盖 `</script`、`<!--` 与 `<script`。已验证：含 `<!--</script>`、中文、反斜杠的字符串经此处理后 `json.loads` 还原相等。
- `course.template.html`：`frame.srcdoc = course.weeks[week-1].html`，删除 atob 与 TextDecoder。
- 测试：`tests/unit/test_build.py` 增加用例，构造含 `</script>`、`<!--`、中文、反斜杠的周 HTML，经 `render_course` 后用 Node `JSON.parse` 解析并与原文相等；`tests/browser/test_course.py` 断言页面成功打开第一周。
- 基线回填 `course.afterStep5`。预期 course.html 约 10.2 MB。

### 3.7 CI 与 Release

`.github/workflows/check.yml` 改为两个 job：

| job | 触发与条件 | 步骤 | 权限 |
|---|---|---|---|
| check | 顶层触发 push、pull_request、workflow_dispatch | 装依赖 → `python tools/project.py release`（check 通过后打包到 `dist/soundblocks-<时间>/`，含 `manifest.json`） → `actions/upload-artifact@v4`，`name: soundblocks-${{ github.sha }}`，`path: dist/soundblocks-*/`，`if-no-files-found: error`；失败时另传截图 | `contents: read` |
| release | `needs: check`，job 级 `if: startsWith(github.ref, 'refs/tags/v')`，普通 push 与 PR 上跳过 | `actions/download-artifact@v4` 同名 artifact 到固定目录 `dist-artifact/` → 断言其下恰好一个 `soundblocks-*` 目录 → 用该目录 `manifest.json` 逐文件核对 sha256 → 按 `manifest.json` 的文件键逐个列出文件名执行 `gh release create ${{ github.ref_name }} <文件列表> --verify-tag`，不用通配展开 | `contents: write`，仅此 job |

验收：push、pull_request、tag 三种触发各跑一次，前两种 release job 必须显示 skipped；下载 artifact 后逐文件 sha256 与其内 `manifest.json` 一致，且与本机同一提交 `project.py build` 的结果一致。

### 3.8 adopted 文件命名与生命周期

- **命名**：`<slug>-<内容 sha256 前 10 位十六进制>.<ext>`，`slug` 为键本身，必须匹配 `^[A-Za-z0-9_-]{1,40}$`，否则导出或工具失败并要求人工命名（当前 300 个无源 blob 的键全部满足，唯一例外 `CELEBRATE_NAT` 无键，slug 固定为 `weekNN`）。`ext` 由 mime 决定。文件名总长小于 64，路径深度固定两层，不含 Windows 保留名、结尾点或空格。
- **内容寻址的后果**：内容变了名字就变。因此被任何清单引用的文件**从构造上不可能被覆盖**；同 slug 不同内容并存是正常状态，旧的由 prune 回收。
- **大小写**：同一目录内文件名的小写形式必须唯一（Windows 文件系统不分大小写），冲突即失败；单元测试覆盖。
- **同内容多键**：只落一个文件，slug 取首次出现的键（按周序、声明序、键序），其余键在清单里引用同一路径。
- **PROVENANCE.json**：只记录 adopted 下的媒体文件（`.mp3` / `.png` / `.webp`），不含 README 与自身；单元测试断言"条目集合 == 目录内媒体文件集合"。每条含 sha256、mime、来源（导出：周文件与提交号；工具：工具名、输入路径、日期）、声明名、键。
- **存活真相**：四周 `manifest.json` 引用的文件才是存活的。`export_embedded_media.py --prune` 删除不被任何清单引用的媒体文件并同步删除其 provenance 条目；prune 之外任何工具不删文件。
- **整批发布**：导出工具与三个素材工具都按同一流程：① 全部产物先写到 `resources/adopted/.staging-<随机>/`；② 在 staging 内完成全部校验（mime、扩展名、slug、大小写唯一、清单 schema）；③ 逐文件 rename 到目标位置，因为名字含内容哈希，rename 只会新增文件，不会改变任何已存在文件的字节；④ 原子写 PROVENANCE；⑤ 最后原子写清单。①② 任一失败时 staging 整目录删除，仓库内任何已存在文件与清单不变。③ 之后失败只会留下未被引用的新文件，由 prune 回收。

## 7. 风险与反向理由

- **副机门槛上升。** 不入库后 clone 不能直接打开课件。对策：CI artifact 与 Release 提供下载；副机命令清单第一条固定为 build。
- **插画导出等于最后一次"把 HTML 当源"。** 导出后 `resources/adopted/` 是真相源，`PROVENANCE.json` 记录每个文件从哪个周文件、哪个提交导出；README 声明它是派生媒体而非原始素材。
- **历史重写不可逆。** 引用快照、bundle 可恢复性验证、精确到七个产物名的清单、对照更新先于强推、副机停工窗口五道保护；清理带来的收益只是现有 221 MB，B 之后不再增长，这一条是用户明知代价后的选择。
- **内容寻址命名让清单可读性下降。** 文件名多了 11 个字符的哈希后缀；换来的是"被引用文件不可能被覆盖"这一构造性保证，以及 Windows 下无需处理覆盖冲突。
- **护栏误报。** 小书多的周可能触线；触线时先看是不是重复媒体，再决定放宽阈值。
- **时间。** 第 1 期与第五周里程碑 2 都落在 09-14 到 09-27 之间；第 0 期一到两天可在本周内完成，第 1 期若与里程碑 2 抢时间，里程碑 2 优先，第 1 期顺延到 W5 之后，代价是第五周再多一份全量拷贝。
- **文档漂移已在发生。** 三方交接规范 v1.1 与方案 §9.2 都已落后于实作，§6 清单逐文件收口。
