## 1. 三方角色

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **用户** | 拍板；上课与回收数据（周检、月测、总表）；人耳听检（音素与单词发音对不对，机器验不了）；两台电脑之间的 push / pull；确认 GPT 的每一步 | 不手改课件 HTML；不在两台电脑同时改同一周的文件；不手工合并 JSON |

| **GPT（副机）** | 按提示词文档两阶段出图；按 §5 参数表调发音并跑管线；把产物按 §6 白名单保存、提交、推送；按需回答用户关于课件使用的问题 | 不手改 HTML（工具生成的 HTML 改动是派生物，允许）；不改任何 `tools/*.py`、`tools/week-checks/*`；不写数据层（2026-09-02 定：数据层归 Claude）；不改风格前缀；不改 README 与 docs；不发明新块类型、新常量、新文件名规则；不解决 git 冲突 |

一句话：**Claude 出内容和结构，GPT 出图和调音并跑管线，用户拍板和听检，仓库是唯一的交接载体。**

**节奏**：每周的审定截止日按课程方案 §5.3"审定截止"列（第 7 周起为开课前 14 天）。步 1 到 5 在主机连续做完再推；步 6、7 在副机；步 8、9 回主机。**一周的文件同一时间只在一台电脑上改**。

**并行规则**：主机做第 N+1 周的步 1 到 5 时，副机可以同时做第 N 周的步 6、7。副机只碰 §6 白名单里第 N 周的路径；`assets/phonemes/` 和跨周复用的单词音频不并行改；README 只由主机改。

### 3.1 副机命令清单 · 配图（步 6，GPT 逐条执行，用户逐步确认）

```bash
git pull                                   # 预期：Already up to date 或快进
# 保存 PNG：assets/weekNN/phoneme/<art键>.png、assets/weekNN/word-cards/<art键>.png、
#           assets/weekNN/book/<art键>.png、assets/weekNN/celebrate.png
python tools/embed_assets.py --target weekNN.html --assets assets/weekNN --dry-run
#   预期："覆盖情况"里四个常量各显示 已就位 数；末尾没有"需要注意"段里的"孤儿图 …"条目。有孤儿图先改名或删除再继续
git add assets/weekNN
git commit -m "第 N 周插画：<数量> 张；dry-run 孤儿 0"
git fetch && git status -sb                # 预期：与 origin 同点或只领先；显示 behind 先 git pull --no-rebase
git push                                   # 出现冲突不要处理，停下告诉主机
```

副机可以真跑 `embed_assets.py`（去掉 `--dry-run`）以便在课件里看图，注入后的 HTML 是派生物，允许一并提交；主机步 8 会重跑覆盖。

### 3.2 副机命令清单 · 发音回炉（步 7，GPT 逐条执行，用户逐步确认）

```bash
git pull
# 改 tools/audio_manifest_wN.json：只改目标条目的 rate / silence_threshold_db / manual_trim（voice 不动，见 §5）
# 先只回炉 1 个代表性键，让用户试听确认声线与节奏，再批量回炉其余键
python tools/gen_audio.py --manifest tools/audio_manifest_wN.json --force --key "<键1>" --key "<键2>"
#   预期：只重生成列出的键；不要不带 --key 使用 --force
python tools/build_audio.py --manifest tools/audio_manifest_wN.json --target weekNN.html
#   预期：七项自检全部 PASS 后才写 HTML；任一 FAIL 不写盘，把完整输出原样交给主机，不要改脚本
git add tools/audio_manifest_wN.json assets/audio_raw assets/audio_processed weekNN.html
git commit -m "第 N 周发音回炉：<键列表>；<改了哪些参数与理由>；自检全绿"
git fetch && git status -sb                # 同上
git push
```

## 4. GPT 工作包

### 4.1 配图包（两阶段）

**阶段一 · 定妆**（本周提示词文档要求新角色时才有）：给三张风格参考图 + 提示词文档 §2 的定妆描述；GPT 出定妆图；用户确认后存为文档指定的 `_char_*.png`。

**阶段二 · 场景**：给提示词文档全文 + 三张风格参考图 + 已确认的定妆图；GPT 按表逐张出。

三张风格参考图固定：`assets/word-cards/pin.png`、`assets/phoneme-mnemonics/s-snake.png`、`assets/wall-nat/natSit.png`。

**不给**：任何 HTML、整个仓库、工具脚本。

**开场提示词**（用户复制到 GPT 会话第一条）：

> 你是这个儿童英语课件项目的插画师，同时负责把图保存到本地仓库并提交。任务：按我给你的提示词文档，逐张生成透明底 PNG，1024×1024，画面里不能有任何文字或字母。
> 画风：文档里的"通用风格前缀"一个字都不能改，每张图都要带；先看我附的三张参考图对画风。文档要求先出角色定妆图的，先出定妆图并等我确认再出场景。文档标"建议跳过"的词不要画。
> 保存：文件名严格等于文档表格里的 art 键加 `.png`，全小写，不能有空格、中文、版本后缀或"(1)"；路径按文档说明放进 `assets/weekNN/` 对应子目录。庆祝图也是 1024×1024，后续由工具缩到 384，你不用管。
> 提交：只按我给你的命令清单执行，只能碰 `assets/weekNN/` 目录；不要改任何 HTML、脚本、文档，不要改文件名规则；push 被拒就 pull 一次再 push，出现冲突立即停下告诉我。有疑问先问我。

### 4.2 发音包（用户听检后需要调整时）

给这些：本周 manifest；`docs/声音积木周课件设计规范_20260831_v1.0.md` 的 §6 和 §11（含三层排查、清楚优先、样本先行）；本文 §5 参数表；待修清单（哪些键、听起来哪里不对，例如"milk 的 k 没了""sad 词尾太重"）。涉及音素录音时再给 `assets/phonemes/README.md`。

**开场提示词**：

> 你只能改 manifest 里目标条目的 `rate`、`silence_threshold_db`（-90 到 -20）、`manual_trim`（只在我人工核听后给出区间时用）。`voice` 不能改：单词和句子是 en-US-JennyNeural，小书是 en-US-EmmaNeural，这是按资源类型固定的。

> 每次改完，把自检输出和"改了哪些键、哪些参数、为什么"整理成一段话给我，我要写进提交说明。

## 5. 谁能改什么 · 音频参数表

| 参数 | 性质 | 值 | 谁能改 |
|---|---|---|---|
| `voice` | **固定**（按资源类型） | 单词、句子、短语：`en-US-JennyNeural`（manifest 顶层）；小书：`en-US-EmmaNeural`（逐条覆盖） | 只允许纠正分类错误，由 Claude 改 |
| `rate` | 默认，可逐条覆盖 | 词 -20%、句 -10%、短语 -10%（顶层按类型）；小书 -30%（逐条） | 副机可改，提交说明写理由 |
| `silence_threshold_db` | 默认，可逐条覆盖 | 全局 -40；小书条目 -60；第三周 71 个塞音结尾词 -60、另 16 个用 manual_trim（优先于本参数），塞音结尾已无默认 -40 条目（规范 §6.1）；覆盖范围 -90 到 -20 | 副机可改，提交说明写理由 |
| `manual_trim` | 可逐条加 | 无默认；窗口取"原始语音起点 −0.05 秒到终点 +0.12 秒"（规范 §6.1） | 人工核听后加，副机可改 |
| 处理链常量（峰值 -3 dBFS、静音验证窗口）、七项自检、提取源注册表、`SOURCE_SPECS` 冻结计数、注入锚 | **固定** | 见 `tools/build_audio.py` | 只有 Claude；计数对不上先查数据形状，是 tripwire 在工作 |
| 音素录音 | **固定为真人** | 见 `assets/phonemes/README.md` | 新增按 README，由 Claude 注入并署名 |

## 6. 换电脑衔接

### 6.1 开工前（任一台电脑）

1. `git pull`；`git status -sb` 确认与 origin 同点、工作区干净。
2. 跑 `docs/项目记忆/换机验证清单.md`（第一次换机全五关；之后至少第 1、2 关）。
3. 读 `docs/项目记忆/README.md` §1"现在到哪一步"和 §4"当前阻塞"。当前在哪个 commit 用 `git log --oneline -1` 看，不信任何文档里写死的值。

### 6.2 离开前

主机：更新 README §1（只写状态，不写 SHA）→ `git status` → commit → `git push` → `git status -sb` 确认与 origin 同点。没有状态变化就不改 README。

副机：不改 README；状态写在提交说明里 → commit → push → 确认同点。有半成品不想提交的，告诉主机，由主机写进 README §4。

### 6.3 副机路径白名单与主机核对

副机的提交只允许触碰：

- `assets/weekNN/**`（本周插画）
- `tools/audio_manifest_wN.json`（本周 manifest）
- `assets/audio_raw/`、`assets/audio_processed/`（本周新增或回炉的键）
- `weekNN.html`（仅工具注入产生的改动）

主机 pull 后核对（基准由命令自算，不写死）：

```bash
BASE=$(git log -1 --format=%h --grep=Claude-Session)      # 最近一次主机提交
git log --stat --format='--- %h %s' "$BASE"..HEAD            # 副机提交触碰的文件必须全在白名单内
```

出现 `tools/*.py`、`tools/week-checks/*`、`docs/`、README 或其他周文件的改动，回滚这些文件，只保留白名单内的改动，并在提交说明里记一笔。

### 6.4 分支与冲突

- 只用 `main`，不建长期分支。同一周的文件同一时间只在一台电脑改。
- **冲突按真相源裁决，不按扩展名**：源 = manifest、`assets/audio_raw/`、PNG、`weekNN-data.js`；派生 = `assets/audio_processed/`、注入后的 HTML。冲突由 Claude 在主机按周次和键合并源文件，然后统一重跑 `build_audio.py`、`embed_assets.py` 重生成派生物并校验。用户和 GPT 不手工合并 JSON 或 HTML。
- push 被拒：先 `git pull --no-rebase`，无冲突再 push；有冲突停下交主机。

### 6.5 不跨机的东西

Claude 本机记忆（真相在仓库 `docs/项目记忆/`）；`tmp/`（已忽略，codex 运行产物）；`.claude/settings.local.json`（已忽略）。Claude Code 在新机器上开工：仓库自带的 `/handoff`、`/tidy-docs` 自动加载；第一条动作是读 README，不是读会话历史。

## 7. 冲突与优先级

- **真相源优先级**：上一周定稿 HTML 的实作 > 周课件规范 > 课程方案 > 本文 > design-doc。"实作优先"只指规范写漏或写错的地方以实作为准并回改规范；实作里的已知 bug 不因此成为规范。
- **GPT 的产物与规范冲突**：规范赢。GPT 提的"优化建议"一律先记成 issue 由用户拍板，不直接落地。
- **谁能改工具**：只有 Claude 改处理链、校验器、注入脚本；GPT 与用户只改 manifest 参数和素材文件。
- **谁能改文档**：本文、周课件规范、课程方案由 Claude 改并走版本号；提示词文档每周一份不回改旧周；README 只由主机改。
