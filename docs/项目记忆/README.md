## 0. 这个项目是什么

**声音积木** —— 给一个 7 岁孩子做的英语自然拼读课件，六年计划的第一阶段。

产出形态是**单个自包含 HTML 文件**，一周一个：音频 base64 内嵌、插画 base64 内嵌、
字体子集内嵌，**零外部资源加载**，拷到任何一台电脑双击就能用（进度存 localStorage）。

| 文件 | 是什么 |
|---|---|
| `week01-v3.html` | 第一周定稿课件（2.6 MB）。六个游戏齐备，是所有后续周次的母本 |
| `week02.html` | 第二周课件（649 KB）。**插画和新音录音都还没补**，见下方阻塞项 |
| `design-doc.html` | 六年计划设计文档，讲教学法判断，不讲实现 |

## 4. 当前阻塞与未决项

按优先级：

1. **第二周素材全缺**。词卡/小书/助记/庆祝图的提示词已备好在
   `docs/插画生成提示词_第二周_20260831_v1.0.md`，图生成后放进 `assets/week02/` 对应子目录
   （**文件名 = art 键**），跑 `tools/embed_assets.py` 注入。
   六个新音的真人孤立音未获取，补齐前按铁律 8 **不给听音按钮**
2. **"冒烟全绿" ≠ 铁律 6 已验证**。`tools/week-checks/smoke_w2_browser.py` 只覆盖了 G3/G4/G5 的
   "结算 + 落盘 + 刷新恢复"，G1/G2/G6 没覆盖——要覆盖得先在页面上下文里把音频播放
   替换成立即完成的确定性桩
3. **待追认 P6**：G4 摆放定为一步式入槽（要改两步式 = `initG4` 加 `selectedTile` 约 20 行）
4. **第三周待决设计题**：G5 造词积木架第一周 12 块、第二周 13 块，第三周按老办法是
   **19 块**，7 岁孩子开始难找。需要人拍板，不许模型默默决定
5. **重跑第一周音频注入会被 tripwire 拦住**（**不影响课件运行**，优先级最低）。
   `week01-v3.html` 的 `G3_PAIRS` 已扩到 3 组（共 6 词），但
   `tools/build_audio.py:376` 的 `SOURCE_SPECS["g3_pairs"]` 仍冻结在 `keys=2, unique=2`。
   **课件本身完好**——`WORD_AUDIO` 已内嵌 56 条、六个 G3 词全在（它们本就是普通词表 `W`
   的成员，由 `words` 源覆盖，与 `g3_pairs` 源无关），实际使用无任何问题。
   只有重跑 `tools/build_audio.py` 时计数自检会 FAIL 并拒绝写入（安全失败，不碰 HTML）。
   这是 tripwire 按设计工作：数据形状变了、manifest 计数没跟上。
   改成 `keys=6, unique=6` 即可，**但先确认扩到 3 组是最终决定**——`pat/pit`、`tap/tip`
   含尚未教学的字母 `p`，这是教学判断不是技术判断
