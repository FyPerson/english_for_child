## 第 1 关 · 仓库拉全了吗

```bash
git clone https://github.com/FyPerson/english_for_child.git
cd english_for_child
git fetch
git status -sb          # 期望：## main...origin/main  且下面没有任何文件
git fsck --no-dangling  # 期望：无 error
git log -1 --format='%h %s'   # 记下这个值，后面几关如果出问题要报给对方
```

**判据是"与远端同点且工作区干净"，不是"等于某个写死的 commit"。**
`git status -sb` 第一行不带 `[ahead N]` / `[behind N]`、下面没有文件列表，就说明
你手上的内容和远端逐字节一致——git 的内容寻址已经密码学地保证了这点，
比对文档里写死的哈希表反而更弱（那种表迟早过期，这份清单的上一版就是这么过期的）。

`git fsck` 查对象完整性，防的是传输损坏这类罕见但真实的情况。

**不要**再去比对某个 HTML 的字节数——那些文件现在不入库了。素材完整性由第 4 关的构建代跑：媒体缺一个字节，构建的媒体覆盖检查就会失败。

## 第 2 关 · 环境依赖装起来

普通构建只要 Python 标准库加 Node，Playwright 只有回归测试要用。

```bash
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
python tools/project.py doctor
```

`doctor` 期望输出四行：Python 版本（≥ 3.10）、Node 可执行路径（**不是 None**）、Node 版本、以及末行

```
PASS environment, Node.js >= 18 and Chromium
```

推荐 Python 3.12、Node.js 22。主机 2026-09-08 实测为 Python 3.12.0、Node v24.11.1。

### 副机还要额外装

配图与调音的依赖不属于普通构建，所以不在 `requirements-dev.txt` 里，但那正是副机的本职：

```bash
pip install pillow numpy imageio-ffmpeg edge-tts
python -c "import PIL, numpy; print('ok')"
python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"
python -c "import edge_tts; print('ok')"
```

## 出问题怎么办

| 症状 | 处置 |
|---|---|
| `git status` 不干净，一堆文件显示已修改 | 多半是换行符差异。`git diff` 看看是不是整文件都在变；是的话不要提交，先处理换行配置 |
| `git pull` 报 unrelated histories 或大量冲突 | 你的 clone 是 2026-09-07 历史重写之前的。**重新 clone**，不要试图 merge 或 rebase |
| `doctor` 的 Node 那行是 `None` | Node 没装或不在 PATH。普通构建也要它，先装 |
| 构建报"失败 N 项" | 看它打印的具体项；数据契约不过就是数据层的问题，不要改校验器绕过 |
| 课件打开一片空白 | 看浏览器控制台报错。内嵌资源损坏的话，`git fsck` 后重新 clone 再 build |
| 音素点了不出声 | 先确认页面有过用户手势（浏览器音频策略）；再看 `resources/assets/phonemes/` 是否完整 |
| `build/` 里有构建以外的文件 | `release` 会拒绝打包。清掉——那个目录只放构建产物，且不入库 |

## 换行符：已统一，无需处理

仓库根有 `.gitattributes`，规则是 `* text=auto eol=lf` —— 所有文本文件在仓库内和
工作区一律 LF，音频、图像、字体、文档显式声明为 binary 不做任何转换。

配套约束：**任何写文本文件的脚本都要用 `newline=""`**（`Path.write_text` 不传这个参数时，
Windows 上会把换行翻成 CRLF，等于把统一好的换行又翻回去）。`tools/` 下已有的写法已全部对齐，新增脚本请照做。
