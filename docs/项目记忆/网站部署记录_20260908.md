## 主机核对（2026-09-08）

副机的记录里留了一条未闭合项：「命令行 HTTP 探测返回 403，未完成线上文件逐字节比对」。主机已补完：

**一、403 不复现。** 正式域名、平台入口、以及不带 User-Agent 三种方式访问均为 HTTP 200。当时那次多半是部署刚完成时的临时状态。

> 比对时注意：`/index.html` 会被 Cloudflare Pages **308 重定向**到 `/`，`curl` 不加 `-L` 会静默下载 0 字节，六个文件会全部"哈希不一致"而线上哈希恰好都等于空串的 `e3b0c442…`。看到这个值就是没抓到内容，不是文件真的不同。

**三、这次比对顺带证明了跨机可重现构建。** 线上文件是副机在 F 盘、`252fe99` 上构建打包的；主机是 E 盘、`15249f9` 上构建的。两台机器、两个提交、不同时间，产物逐字节相同。`check` 里的可重现构建作业只验同机双构建，这是跨机的实证。

**四、线上课件内容仍是最新的。** `252fe99..15249f9` 之间只改了 `docs/`（21 个文件）与 `tools/check_doc_claims.py`，`frontend/`、`resources/`、`project.json` 一个字节没动。**不需要为这些提交重新部署。**

## 后续更新怎么做

```bash
python tools/project.py release        # 完整回归通过后打包到 dist/<版本>/
```

然后在 Pages 项目里创建新的生产部署，上传该目录或其 ZIP。**不要上传整个源码仓库。** 正式域名不变，续用现有 Pages 项目。

需要重新部署的判据：`frontend/`、`resources/`、`project.json` 或构建工具有改动。只改 `docs/` 不必重新部署。

回退：重新上传保留的上一版发布目录。Direct Upload 项目后续可以改用 Wrangler 或 CI 上传，但**不能直接切换成 Pages 内置 Git 集成**。

## 边界

- 浏览器实测只做到「能进合并课程、显示第一周首页、音素播放按钮、第二三周解锁导航」。**不代表已完成人耳试听或真机验收**——那两项仍按三方分工 §1 归用户与主机。
