# 降级要换形态，验证降级的断言要锁对维度

**Why**：第二周移植时同一件事被连着咬了三口，全在"能力暂时缺位"这个场景上。

1. **降级只做了一半（codex 首审唯一的 high）**。本周七个新音没有真人录音，
   给首页积木点亮墙"降级"的做法是把 `data-sayph` 删掉——但元素**仍然是 `<button>`**。
   结果是一排可聚焦、可点击、点了毫无反应的空壳，对触屏和读屏都是误导，
   直接违反项目**铁律 8**。同一次改动里 `tileHTML` 是分支到 `div` 的，点亮墙那处漏了。
2. **断言恰好把它放过去了（复审 R-5）**。冒烟写的是 `.tiles-demo .tile[data-sayph]` 计数为 0
   ——"button 还在、只是没了属性"这种错法完全通得过。**这个 bug 当初就是被这条断言放过的，
   修完之后断言却没变**，等于下次同样的错还会再漏一次。
3. **断言写死了瞬时状态**。插画是分批补的，那几条"缺图降级"断言写的是"一张图都没有"
   （`.wcard__art` 计数为 0 之类）。图一旦到位，测试会因为**错误的原因**变红
   ——不是代码坏了，是断言过期了。

另外两处同类：`.g1card__ico`（36px 固定方块）和 `.book__art`（220px 固定方块）在缺图时
只清空了内容、没收起容器，留下两个真空洞。**只填空串不够，固定宽高的空容器照样是个洞。**

**How to apply**：

- **降级 = 换形态，不是删属性**。每次做"这个能力暂时没有"的处理，问一句：
  **去掉能力之后，这个元素还应该长成原来的样子吗？**
  有录音渲染 `<button data-sayph>`，没录音渲染 `<div role="img">`，class 和视觉态保持一致。
- **区分"只承担该能力"和"另有行为"的元素**。同样是字母积木：
  `tileHTML` / 点亮墙只负责发音 → 无录音时换成 div；
  G4/G5 积木架点了要摆词 → **保持 button**，只摘 `data-sayph`、`aria-label` 改成"字母 x"。
  一刀切会把游戏改坏（规范 §5.3 已按这两类拆表）。
- **回归断言的判据：这个 bug 原样再犯一次，我的断言会不会红？** 会红才算修完。
  锁**元素类型**（`tagName === 'DIV'`），不要只数属性；
  缺图容器要断言**容器不存在或 `getBoundingClientRect()` 宽高为 0**，不要只断言里面没内容。
- **断言配对关系，不要断言瞬时状态**。素材是分批到位的，正确写法是
  "图在 → 必须渲染出来；图不在 → 必须连容器一起收起"，先从页面读回 `Object.keys(WORD_ILL)` 之类再分流。
  写死"现在一张图都没有"的断言，等于给未来埋一颗定时炸弹。

> 这条对**第二周补素材**直接适用：图和录音都是分批到位的，改断言比改代码更容易出错。
