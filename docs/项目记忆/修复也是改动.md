# 修复也是改动：删除旧防护前必须盘点其完整防护范围

**Why**：2026-08-29 v3 P0 编码段同一模式三次实证——每次都是"修复行为本身"引入或漏掉问题：

1. 修预筛 L12（词→词组加 300ms 间隔）时删了 v2 的 `saySeq` 校验，只用 `laterOnce` 防切页
   → codex 抓出 high：同页新请求会被迟到的 phrase 反杀。
   `saySeq` 的防护范围（同页任意新请求）没有被完整盘点，替代方案只覆盖了其中一条。
2. 修尾静音死判据（eps 0.03→0.06）时只看了"LAME 填充恒差 45ms"这一个证据，
   没有盘点新阈值的误伤面 → 塞音闭塞段（52–68ms 连续分布）被硬切一刀，`nip`/`snap`/`book` 误判。
3. G1 的 `cancelled` 处理修了回调层（`roundToken`）后，折叠场景仍漏了物理层（音频继续播）
   与 UI 层（顶部条可复活隐藏卡）→ codex 又一条 high。

**How to apply**：

- 删除 / 替换任何既有防护（令牌、校验、workaround、阈值）前，先写出它防护的**全部**场景清单，
  逐条确认替代方案覆盖；覆盖不了的显式接受并记录。
- **异步 UI 的取消语义按三层枚举设防**：
  ①**回调层**（陈旧回调凭令牌判废）
  ②**状态层**（UI 状态复位 / 互斥）
  ③**物理层**（音频 / 定时器 / DOM 残留真正停掉）。
  一层防不住另外两层——v3 的 G1 最终是 `roundToken` + `_g1Reset` + `AudioBus.stopAll`
  三层各司其职才收口。
- 判据类修复（阈值 / 容差）优先找**语义判据**（如 EOF-flush 配对关系）而非调数值
  ——连续分布上任何数值切一刀都会误伤。

> 播放层（`week01-v3.html` 约 772–990 行）已 0-HIGH 收敛，改它之前先读这条。
